Map the paradigm-families of a practice using the Structural Paradigm-Sweeping Framework loaded in Step 0. The sweeper makes chart acquisition runnable: it recasts the topic as a practice, perceives the practice's approach-space family structure via the probe pipeline, and emits a persistent map whose entries are copy-pasteable seeds for downstream loops — without selecting among them, diving any of them, or generating solutions. **This spec is v0-provisional — see the reference's §6 Validation Debt.**

## Instructions

1. Read the input and consume it. It supplies a **raw topic** (may be object-domain-phrased — recasting is this discipline's first act, never the caller's duty) + optional **goal** (the practice-goal the seeds will echo) + optional **dial** (`in-session | persisted`; default `persisted`) + optional **out-path** (an inquiry chain passes its folder).

2. Execute the full Structural Paradigm-Sweeping process described in `references/paradigm_sweeper.md` (the "Execute the Paradigm-Sweeping Process" section): Receive → Recast (probe 0; recorded in the header) → Sweep (probes 1–5; all mandatory for a persisted map) → Admit & demote (the membership test per candidate; Excluded with the failed conjunct named) → Seed (the capped seed-block per entry; the anchoring guard stated once) → Persist → Assess (telemetry + verdict).

3. Save the map (unless differently stated in additional instructions!):
   - **If an out-path was given** — save `paradigm_sweep.md` there (an inquiry chain passes its folder).
   - **Otherwise** — save under `devdocs/sweeps/<practice-slug>/paradigm_sweep.md` (create the directory if needed).
   - **Re-runs on the same practice** follow the reference's §3.6 (the lazy pair: create/load `_sweep.md`; emit a versioned map; stale-flag in the index only; author the new map's ✓ column empty).

4. Record the user's input at the top of the map: `## User Input` followed by the raw input verbatim. This preserves the pre-recast topic beside the recast for audit.

5. Emit the self-assessment verdict at the end of the map: **PROCEED** or **FLAG** (with the flagged condition named), per the reference's §4.4.
