## Step 4 — Question tree (pieces-as-questions + verification criteria)

### Q1 [FRAME, first] — the reframe adjudication
**Question:** Is the user's critique ("using papers for breakthroughs is not useful") right?
**Answer:** WARRANTED-WITH-A-CORRECTION (non-sycophancy both ways). (a) TRUE part, credited fully: the success-criterion, framed as breakthrough-hunting, mis-describes where value lands — empirically the recent run yielded seeds (17, 19) + confirming + mirrors + zero breakthroughs; the genuine imports were early. The user correctly diagnosed a mis-set goal. (b) OVERSTATED part: "breakthroughs are useless" conflates the breakthrough VERDICT (usually NO) with the breakthrough GATE (the import test — the filter that makes a seed credible; paper 20's seed collapsed AT it, 17/19's survived it). (c) SYNTHESIS: reframe the GOAL (breakthrough-hunting → seed-harvesting) while KEEPING the GATE (the import test = the seed-quality filter); breakthrough demotes from "the point" to "a seed already grown / the top of the ladder."
**Verification:** does it credit the true part FULLY (not defend the status quo)? Does it keep the gate on the MERITS (not rubber-stamp the discard)? Is the synthesis (reframe-goal / keep-gate) stated up front? Piece-Level Inversion run (see interfaces)?

### Q2 [★ THE CENTER] — the seed definition
**Question:** What IS a seed (the seed_generator's sense), given "seed" is already overloaded?
**Answer:** A seed is an **OUTPUT germ** (the yield of extraction — distinct from the two existing INPUT senses: the innovate-seed [a trigger generation works from] and the paradigm-sweeper seed-block [a copy-pasteable launch-point]), **ANCHORED** to a specific harness concept (a canon frame / an un-built component / an open design question — this IS the user's "relate to our concepts" constraint, and it is the content of the existing change-a-decision test), **GATED** (it must connect to something the harness does not already own), with **DEFERRED payoff** (it pays off after development — unlike an import, which pays off now). It comes in **TWO GRADES**: LIVE (clearly changes a future design decision → ACT; papers 17, 19) and NASCENT (an interesting, anchored development that might mature → WATCH; e.g. paper 20's single-data-point hypothesis). The two grades resolve the user's "interesting development and understanding" intent (nascent = the looser catch) without discarding the gate (the gate moves from *capture* to *act*). On the verdict-ladder: breakthrough > import > LIVE seed > NASCENT seed > confirming-plus > mirror > confirming-nothing — the seed is the germinal middle.
**Verification:** does the definition resolve the 3-sense overload (name it as the output-sense)? Are all four properties present (output / anchored / gated / deferred)? Do the two grades genuinely resolve the interesting-development tension (not hedge it)? Is distinctness-from-senses-1+2 prosecuted (Piece-Level Inversion)? Is the lifecycle-link (harvest-seed → later innovate-trigger) stated so the family resemblance doesn't read as a contradiction?
