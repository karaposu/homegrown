## Phase 2 — Generate (7 mechanisms × 3, compact)

### 1. Lens Shifting (Framer)

- **1G — the launch-checklist lens (adopted as the rendering).** The roadmap as a pre-flight checklist: items in strict order, each with a GO/NO-GO box that is the user's, alternatives as "configuration options" per item. Fits the plan-not-execution bound (the checklist hands over the GOs) and makes the window item unmissable (it's the only one marked IRREVERSIBLE-IF-SKIPPED).
- **1F — the "one short session" lens (focused, adopted).** The worklist already promised "all of Tier 1 ≈ one short session"; the refreshed roadmap should KEEP that promise visible and show it got CHEAPER (the field is free now; Turn1=D4 is one move): steps 1+2 together ≈ one sitting. The user should leave knowing the whole opening is an afternoon, not a project.
- **1C — the "this roadmap flatters the session" adversary (contrarian).** "Conveniently, the new findings made everything cheaper and this very inquiry's exhaust is the recommended field — the session grading its own homework?" Answer: every step traces to a PRE-session commitment (the worklist's own items 1/2/3/4; the Expedition's own MUST; the ladder's gates); the session's findings enter only as re-pricings, and the one place the session's output is recommended (the `_route.md` field) is the LADDER'S CHEAPEST RUNG, not its richest (the Navigator root-run — pre-session doctrine — remains the quality option). Adopted as a one-line honesty note in the finding's reasoning.

### 2. Combination (Generator)

- **2G — the pre-registration file × assistant-drafting = the skeleton-now option (adopted).** The finding can include the file's SKELETON (six indicator headings + the three required fields each, with the north-star definitions quoted) so "assistant-drafts-user-commits" becomes a 5-minute review instead of a from-scratch write. The commitment stays the user's (they review and save); the activation energy drops to near zero. This is the same mechanization-beats-exhortation pattern as step 4.
- **2F — Turn 1 × the selections file × this inquiry's exhaust = the worked first-turn script (adopted).** One concrete script: "open this inquiry's `_route.md` → pick one route → create `devdocs/selections.md` with the v1 table → write one admitted entry (route-ref / rationale / run-conditions / invalidate-if / goal) → done; Turn 1 is recorded." Five actions, ~10 minutes. The script makes the unified move undeniable.
- **2C — the fork × the gate numbers = the convergence observation.** Mixed isn't just safe — it's FASTER to the L2 gate than Expedition-now would be even ignoring the MUST: shakedown failures inside a committed 20-turn arc cost the arc; 3 cheap organic turns absorb the failures, and the Expedition then runs clean — likely net-fewer total turns to 10-recorded. Adopted as the fork's deciding line.

### 3. Inversion (Framer; at the meta-decisions)

- **3G — invert the mixed recommendation: when is Expedition-NOW right?** Only if the shakedown MUST were satisfied some other way — and it can't be: zero recorded turns exist, so nothing has been shaken down. Even maximum urgency lands on "do 2–3 turns first" — which IS mixed. The inversion collapses; the recommendation is over-determined. Adopted (stated as "Expedition-now reduces to mixed under its own MUST").
- **3F — invert the SEE-rung pick: when is the Navigator root-run the RIGHT Turn-1 field?** If the user wants Turn 1's choice to be a GLOBAL bet (the best route in the whole project), the inquiry-local `_route.md` under-serves it. Honest condition: pick the Navigator rung when Turn 1 should set the Expedition's DIRECTION (a global decision), pick the free rung when Turn 1 is just the habit's first rep (the worklist's "recorded beats wise"). Adopted — the pick-condition got sharper (it depends on what Turn 1 is FOR, which is itself the user's call).
- **3C — invert the skeleton-now option: does drafting it overstep the user's seat?** The risk: pre-registration's epistemic value comes from the USER's commitment; an assistant-drafted file the user rubber-stamps could carry the assistant's biases about what evidence counts. Resolution: the skeleton includes structure + the verbatim north-star definitions but leaves the EVIDENCE and MEASURE fields as prompts-with-examples (the user fills the load-bearing cells). Drafting the form ≠ drafting the commitment. Adopted with that boundary.

### 4. Constraint Manipulation (Framer; both directions)

- **4-ADD (generic, adopted).** Every step's alternatives table gets a **pick-when** column (the condition under which you'd choose it) — no bare options.
- **4-ADD (focused, adopted).** The gate-targets table gets a **what-opens-it** column (the committed trigger, verbatim from its source) — making "named-not-next" checkable.
- **4-REMOVE (generic).** Drop the gate-targets section (just the four steps)? → loses clause-2 coverage for the path's rest and invites "what about L2?" follow-ups; the horizon is part of the answer. Keep.
- **4-REMOVE (contrarian).** Drop the worklist edit-list (just answer)? → leaves the standing file actively misleading (item 7 superseded; stale vocabulary) — the reconciliation was articulated as an endpoint. Keep, application still the user's.

### 5. Absence Recognition (Generator; both levels, bidirectional)

- **Patch-level:** (i) **the naming-veto rider** — the Pipeline finding's naming options (Selector/Dispatcher/meta-loop) are a standing one-line user call that gates the worklist edit's WORDING; the roadmap should carry it as a micro-item inside the reconciliation (absent from the four steps — correctly, it's not work, it's a word). (iii) **the Expedition's pre-conditions checklist** — when mixed's trigger fires, what must be true? (selections file smooth ≥3 turns; the checker ideally built; a goal chosen; budget cap set) — one compact line so the handoff is concrete.
- **Redesign-level:** none — the five-piece shape holds.
- **Bidirectional (already-present):** the roadmap's whole opening is ALREADY two-thirds mechanized by what exists (aMVLwr's exhaust; the selections-file design; this inquiry's `_route.md`) — the steps are small because the session built their tooling. Stated once, honestly (with 1C's guard).

### 6. Domain Transfer (Generator; native source included)

- **6-native (adopted).** The corpus's own **pre-registration practice** (the Thesis finding's MUST) is the scientific-method transfer already committed — the roadmap just executes it; no new analogy needed.
- **6-different (mountaineering).** REJECTED — the launch-checklist lens already carries the ordered-irreversible-steps image; a second metaphor dilutes.
- **6-different (the "definition of done").** A scrum-ism worth one line: each step ends with an explicit DONE condition (the file exists with timestamp; the entry is written; the choice is recorded; the mechanism is installed) — adopted into the checklist rendering.

### 7. Extrapolation (Generator)

- **7G — where the roadmap lands if followed.** Extrapolate 3–4 weeks: pre-registration committed; selections file at ~10+ admitted entries with outcomes filling; the Expedition complete or mid-arc; L2 proposal-data accumulating; the checker built — i.e., the L2 gate in sight with evidence, not vibes. One closing line for the finding (the "what success looks like" horizon).
- **7F — the failure extrapolation.** If the window is burned (Turn 1 before pre-registration), the indicator program loses its falsifiability forever — the project can still climb, but the consciousness-gradient claims drop to anecdote-grade permanently. Stated once, plainly — it's WHY step 1 is step 1.

Naming this makes the fork genuinely decidable. Adopted into the fork's presentation.
