## Phase 2 — Generate (full mechanism coverage)

### Generators

**G1 — Combination (the unifying move).** Combine Axis-1 (necessity) + Axis-2 (flexibility) + Axis-3 (grain) → emergent: **a single typed input contract** — "routelister(scope: Territory | ConceptIdentity, goal: Concept[fuzzy-ok]) where the scope-type is selected by the traversal axis, supplied source-agnostically." None of the three axes alone is the contract; the contract emerges at their intersection. → feeds P5.

**G2 — Absence Recognition (patch + redesign, both mandatory).**
- *Patch-level:* what's missing from the contract as stated? The **goal's role under the epistemic axis** — when the goal is fuzzy, the goal is not just a *filter* but itself a *target* (routelister emits goal-refining routes). The contract should name the goal as required-but-possibly-an-output-target, not only an input filter. → refines P1.
- *Redesign-level (what's already present in different form):* is routelister's "scope" something the project already has un-articulated? YES — routeman's §3.2 read-policy already supplies "what to read" (a scope) in process form; the meaning-level "scope" is the un-articulated contract behind that mechanism. So "scope as Axis-1 necessity" is not new-from-nothing; it's the articulation of what the read-policy already presupposed. (Guards against treating the contract as more novel than it is.)

**G3 — Domain Transfer (native + different).**
- *Native (programming — the type-contract/function-signature frame):* a function has required parameters (necessity), accepts them from any caller (source-flexibility), and the parameter TYPE varies by overload (grain). routelister's contract maps cleanly: required args (scope+goal), caller-agnostic, type-by-axis. The "no-input → can't run" is just "missing required argument." Import: state the contract as a **typed signature with an overload per axis**. → strengthens P5 + reframes F1.
- *Different (cartography):* a survey needs a region to survey (scope) and a purpose-of-survey (goal); it is indifferent to whether the region is handed over as a map, a photo, or a walked boundary (source-flexibility); and the survey grain differs for "map the whole county" (breadth) vs "map this one estate in detail" (depth). Confirms all three axes from outside the project's vocabulary.

**G4 — Extrapolation.** Extend forward: as routelister runs on richer territories with many manifestations and fuzzier goals, does the contract hold? At the limit (a vast territory, a barely-formed goal), Axis-1 still binds (you still need *a* scope and *some* directional bias, even if "sharpen this fuzzy goal" is itself the bias) — the epistemic axis absorbs the fuzziness. The contract does not break under extrapolation; it degrades gracefully (fuzzier goal → more epistemic routes). Confirms the fuzzy-goal refinement scales.

### Framers — Piece-Level Inversion (generates the foils)

**F1 — Invert P1 (necessity).** Assumption: "routelister requires a scope + goal as input." Reversed: *"routelister needs NO input — it generates the concepts itself."* What follows: routelister would be a generate-from-nothing engine. **Depth check (system-level):** inverting again — "if it needs nothing, what distinguishes its output from hallucination?" → nothing; there'd be no territory to ground the enumeration in. This collides with routelister's settled IS-NOT ("generate-from-nothing") and its perceive-by-enumerate character. → Foil is a clean boundary marker (the contract's necessity is what separates routelister from invention).

**F2 — Invert P2 (flexibility).** Assumption: "folder-independent by-construction." Reversed: *"routelister IS bound to `devdocs/inquiries/`."* What follows: routelister could only run inside the runner's inquiry tree. **Depth check:** invert again to system-level — "what would make a domain-agnostic discipline folder-bound?" → only a loop-role baked into identity (exactly routeman's original category error). So folder-binding would re-import the defect routelister was built to shed. → Foil re-confirms folder-independence by exposing that its negation = the original routeman mistake.

**F3 — Invert P3 (grain-is-meaning).** Assumption: "the mode-grain is a meaning-level contract axis." Reversed: *"the grain is pure process — which grain to read is a runtime mechanic, not the contract."* What follows: Axis-3 would drop out of the meaning-layer contract. **Collision/refine:** partly TRUE — the *selection mechanism* (how the axis is chosen) IS process (already deferred). But *that the required input KIND differs by axis* is a statement about what the operation requires = meaning. → Foil sharpens the meaning/process seam: grain-KIND = meaning (stays in contract); grain-SELECTION = process (deferred). REFINE, not kill.

**F4 — Invert P4 (relationship) — THE critical foil.** Assumption: "this is confirm-refine-extend, NOT a flip." Reversed: *"this IS a flip — routelister's input contract OVERTURNS 15-48 (state ≠ territory; routeman's input is gone)."* What follows: the finding should declare CORRECTS/supersedes-the-contract, like 19-00 flipped. **Depth check (system-level + multi-axis):** test the *existence-axis* — "is there ZERO preservation of 15-48's input?" → NO: territory ⊇ completed-cycle-state, so routeman's "state" input is a *proper subset*, fully preserved as a special case. A generalization that contains the prior case is not an overturn. Contrast 19-00, which flipped a *verdict* (wrong-tool → right-tool) — here no 15-48 claim is negated; each is widened. → Foil is KILLED, and killing it is exactly what earns the confirm-refine-extend verdict (it's the strongest objection, and the verdict survives it).

**F5 — Invert P5 (synthesis).** Assumption: "the contract is genuinely THREE axes." Reversed: *"it's not three — Axis-3 (grain) is just Axis-1 (necessity) restated; there are really two."* What follows: collapse to 15-48's original two axes. **Refine:** Axis-1 says *that* a scope is required; Axis-3 says *which KIND* of scope per traversal axis. Related (grain refines necessity) but not identical — a two-axis statement cannot express "territory for breadth, concept-identity for depth" without Axis-3. → Foil REFINES the framing: Axis-3 is a *dependent refinement* of Axis-1, not an independent peer — but it is a distinct contract clause, so "three clauses, one dependent" is the precise statement. (Prevents over-claiming three fully-independent axes.)

### Constraint Manipulation (both directions mandatory)
- **REMOVE:** drop "goal required" → can routelister run on scope alone? It could enumerate *every* concept-identity with no directional bias — producing an undifferentiated dump, not routes-toward-a-goal. So the goal-constraint is load-bearing (it's what makes outputs *routes*). Confirms goal-necessity. (REMOVE "scope required" already covered by F1.)
- **ADD:** add "goal must be CRISP" → breaks the fuzzy-goal refinement (09-53) and excludes the epistemic axis. The added constraint is *too tight* — it would forbid valid fuzzy-goal runs. Confirms goal-may-be-fuzzy. → both directions productive.

The contract holds under the most folder-hostile lens → strongest support for folder-independence-by-construction.
