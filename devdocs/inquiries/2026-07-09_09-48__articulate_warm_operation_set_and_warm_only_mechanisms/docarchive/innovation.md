## (3) ITEM B — the conflict mechanism (detect + escalate, one mechanism)

**(a) The conflict-detection operation (an identify-move):**
```
  OPERATION  conflict-detection            (warm-only; context-enabled)
  INPUT      the re-anchored request premise  +  the surfaced material
  PROCEDURE  identify INCOMPATIBILITIES between what the request ASSUMES
             and what the project REALITY (surfaced) shows.
             2-shape:  identified-conflicts-list  |  explicit-empty
             DON'T adjudicate (name the conflict; don't decide who's right)
  OUTPUT     an identified-conflicts-list (with severity)  →  feeds the verdict
```
It is the **context-enabled sibling of cold's ambiguity-identify** (`:132`): cold identifies openness *within* the request; warm additionally identifies conflict *between* request and reality. Same 2-shape, same don't-adjudicate DNA. Verified **unowned** (surfacing = internal-tag-consistency only `:288`; sensemaking runs later/deeper).

**(b) The escalation ladder:**
```
  conflict severity →
    none                                   → HIGH-PROCEED         (normal warm)
    resolvable by re-anchor                → re-anchor + MED-FLAG  (conflict noted, proceed)
    severe: premise contradicted
          + unresolvable by re-anchor
          + would waste the pipeline        → HIGH-FLAG + clarifying-question PAYLOAD
```

**(c) The emit / runner division (the canon-safe part):**
```
  DISCIPLINE (articulate_warm)  EMITS:   the conflict-list + the verdict + the question-payload
  RUNNER (traverse step 8)      SURFACES / ASKS / BLOCKS
```
The discipline never pauses, asks, or halts (NOT-List#2 `:133` / Stance#3 `:117` preserved). The **asking lives at the runner** — exactly where user-interaction already lives, and exactly as re-surfacing is the runner's act (09-05).

**(d) Autonomy-degrade:** block-and-ask (the severe rung's "wait for the answer") needs an operator. Under autonomy → **degrade to flag-and-best-effort** (emit HIGH-FLAG, record the conflict, proceed with the best re-anchored framing). Block-and-ask is an **operator-present-only runner policy**, not a discipline halt-gate.

**Honest sizing:** *reused* = the FLAG action + the runner surface-path. *New* = a **content-conflict flag-condition** (the verdicts are currently operational-only `:234`) + the **question-payload** + a **runner block-policy** dependency.

## (b) ASSEMBLY EMERGENT (assembly check)

Composing the design, a **lens** emerges: **for any cold-vs-warm (pre-context vs post-context) pass, sort operations by their relation to context — carry the context-invariant, re-run the context-sensitive (on the did-it-move trigger), and *add* the operations context newly enables.** Context is the independent variable; everything else sorts by its relation to it.

**★Sized honestly:** this is a **useful lens grounded in this dive's specific symmetry** — essentially a restatement of "context is what changed between the two passes, so classify everything by its relation to context." It is **not a new thesis**, and it doesn't generalize beyond two-phase context-bootstrap designs. Flagged: **derived-from-this-symmetry, modest** — do not inflate into a universal design law. Its whole content is *use context as the sorting key*.

## (c) THE REQUIRED INVERSION — principled tightening, not scope creep

- **Reading 1 (scope creep):** "warm should re-run more operations *and* gain a new operation — the minimal design was under-built; this is just piling on."
- **Reading 2 (the inversion):** the design actually makes warm's boundaries **sharper**, not merely bigger. Every "expansion" comes with a **restriction**: Item A's trigger-gate *restricts* re-runs to *what-actually-moved* (not "re-run everything" — the maximal reading is explicitly killed); Item B stays *inside* the identify-DNA (doesn't adjudicate), *defers* asking to the runner (doesn't pause), and *degrades* under autonomy (doesn't deadlock) — three restrictions. So warm does **exactly what context licenses — no more, no less.**
- **Landing: principled-tightening-not-scope-creep.** ★Anti-sycophancy — the honest core: the user's **two prompts** did the real work. "articulate_warm just uses MQ2 — maybe more?" *exposed* that Item A was under-specified (thin, MQ4 mis-tiered). The conflict-scenario ("how should warm proceed if something big is wrong?") *exposed* that Item B was a **blind spot** (a whole warm-only capability the design never named). The dive's contribution is a **principle** (context-sensitivity) that both fills the thin spot and bounds the fill — but the *prompts* found the gaps. Credit them, not the synthesis.
