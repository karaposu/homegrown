### P3 — The four gap fix-directions

**Principal fills (mechanism per gap):**

- **GAP-A fix (Domain Transfer + Combination) — the meta-loop as MENU COMPOSER.** *Source domain (computing-native):* a query planner / aggregator that assembles a result set from multiple data sources. *Fix:* the meta-loop, as the loop-aware control layer, **composes the full next-move menu** = routelister's concept-routes (from the perception layer) ⊕ the loop-control moves (terminate/widen/re-run/different-approach/merge/unblock — which the meta-loop can offer *because it holds the loop state*). routelister doesn't enumerate loop-control moves; the meta-loop *adds* them. Intervention shape: **ADD-CONTENT** (a meta-loop spec section: "Next-Move Menu Composition"). This dissolves the homelessness without touching routelister.
- **GAP-B fix (Absence Recognition patch) — specify REVISIT as a `_meta_state.md` operation.** The store exists; author the operation: on each cycle, the meta-loop may *resurrect* (re-open a prior-killed candidate), *invalidate* (retire a prior-survived one), or *revert* (undo a refinement) — recorded as verdict-evolution entries in `_meta_state.md`. Shape: **ADD-CONTENT** (meta-loop spec).
- **GAP-C fix (Combination) — a routelister loop-role section.** In routelister's (to-be-authored) spec, a section documenting the composition contract: *what it consumes* (a completed cycle's artifacts are just a special case of "territory + goal" — the cycle's output becomes the territory, the next inquiry's focus becomes the goal) and *what it emits to the meta-loop* (the concept-route-map the meta-loop selects from). Shape: **ADD-CONTENT** (routelister spec). Critically — this documents the *role*, not loop-relative *identity* (guard-compliant).
- **GAP-D fix (Lens Shifting) — draw the two-memories boundary by purpose.** Reframe the two memories by *what question each answers*: the **index** answers "what concepts exist in this project and how deep is each?" (within-discipline concept-map, perception-store); `_meta_state.md` answers "which moves has the meta-loop taken across inquiries, and how have verdicts evolved?" (cross-inquiry traversal, control-store). They *reference* (the meta-loop reads the index to know what's enumerable) but don't *duplicate* (the index never stores traversal history; `_meta_state.md` never stores the concept-map). Shape: **ADD-CONTENT** (a boundary statement in both specs).

### P4 — The re-admission guard

**Principal (Constraint Manipulation, both directions):**
- *ADD-direction:* add the constraint "every loop-harmony fill must land at the meta-loop / runner / or as a *role-doc* in routelister — never as loop-relative *identity* in routelister." **Piece-level Inversion (guard-soundness axis):** *Assumption:* "fills must not re-admit loop-roles to routelister." *Reversal:* "re-admitting loop-control to routelister is fine — it makes the menu whole in one place." *What follows:* routelister re-acquires loop-relative identity (the 7 types are loop-bound) → re-imports the exact `01-11`/`18-17` defect the redesign removed; the discipline stops being standalone/any-territory. *Depth-check (system-level):* the system-level statement is "a discipline's identity must be loop-independent; loop-coupling belongs to the composition layer" → the reversal violates it. **Inversion tested → rejected; the guard holds** (Foil F3 = "re-admit to routelister," KILLED).
