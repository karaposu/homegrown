## Phase 2 — Generate (full 7-mechanism coverage)

### Generators

**G1 — Combination.** Combine P1 (procedure) + P2 (individuation) + P3 (scoping) + P4 (bias) → the unified concept-listing operation: *sweep the goal-relevant territory; as you sweep, individuate items into a running set of concept-identities; frame each identity as a typed route; terminate at identity-resolution convergence.* The procedure and the pivot are one loop, not separate stages.

**G2 — Absence Recognition (patch + redesign).**
- *Patch (the concrete operational gap):* Sensemaking gave individuation's *signals* but not its *procedure* (how the signals are applied). The missing piece: **online/incremental clustering.** As routelister sweeps, it maintains a running set of identities; for each new item it tests it against the existing identities via the signals — *does this share a referent with / is it a manifestation-of an existing identity?* If yes → attach as a manifestation of that identity; if no (or uncertain → lean-to-split) → start a new identity. This **operationalizes the signals into a procedure**, and it dodges two traps: it's not O(n²) pairwise, and it sidesteps the transitivity problem (an item joins one bucket or starts one — no inconsistent pairwise web). → candidate **OC (online clustering)**.
- *Redesign (already-present):* the *sweep* is already given (surfacing traversal + routeman's "enumerate the full set"); the genuinely new articulated step is the individuate-into-running-identities clustering. So the procedure adds one operationalized step to an existing substrate, not a new framework.

**G3 — Domain Transfer (native + different) — the de-risking move.**
- *Native (data — entity resolution / record linkage):* "is this record the same entity as that one?" is a *mature, solved* practice — matching signals + blocking + a confidence judgment. Individuation IS entity resolution over concept-artifacts. This directly refutes "undecidable": entity resolution is routine (imperfect, calibration-dependent, but tractable) — exactly the shape claimed (soft, signal-guided, lean-biased).
- *Different (library science — FRBR):* cataloging long ago solved "same intellectual work, many manifestations" with the **Work → Expression → Manifestation → Item** hierarchy — *literally* routelister's identity↔manifestation ontology. A librarian deciding whether a new book is a new *edition* (manifestation) of an existing *work* (identity) or a new *work* makes exactly routelister's individuation judgment, goal-relative (to the catalog's purpose), routinely. **FRBR is the strongest external proof that the ontology + individuation are a known, tractable practice, not a novel undecidable problem.**

**G4 — Extrapolation.** As the territory is swept and depth runs accumulate, the running identity-set *converges* — individuation decisions stabilize into the project's concept-map (the fixpoint, `21-01`). So individuation isn't a one-shot risk; it's an accumulating, self-correcting cluster that gets *more* stable with use (calibration trajectory).

### Framers — Piece-Level Inversion (foils)

**F1 — Invert P1 (procedure).** "Drop the individuate step — just list items." → **KILL** — that IS `/surfacing` (item-granularity, no identity-unit); loses routelister's distinctive core.

**F2 — Invert P2 (individuation).** "Individuation is undecidable / impossible." → **KILL** — goal-relative decidability (the quantifier resolution) + entity-resolution and FRBR are *mature practices* doing exactly this. The undecidability was a universal-partition scope error.

**F3 — Invert P3 (scoping).** "No scoping — list every identity exhaustively." → **KILL** — overload; identity-resolution + goal-bias + the frontier-flag bound it.

**F4 — Invert P4 (bias).** "Lean-to-merge — fewer, cleaner identities." → **KILL** — over-merge HIDES a concept (info-loss-in-the-dark, unrecoverable); the recoverable failure is split.

**F5 — Invert P5 (OT0).** "The HOW is still undefined — 'use signals + judgment' is a non-answer." → **REFINE** — with the online-clustering *procedure* (OC) + the concrete signals + the lean-to-split bias + the decidability resolution + the entity-resolution/FRBR grounding, it IS a defined mechanism. The residual softness is *calibration accuracy*, not undefinedness — and softness is correct for a semantic judgment (entity resolution is soft too, yet defined).

**F6 — Invert P6 (synthesis / over-formalization + self-ref).** "The online-clustering procedure over-formalizes a soft judgment into a hard algorithm." → **REFINE** — OC is a *procedure for applying* the signals (which bucket does this item join?), but the per-item signal-evaluation stays a *soft judgment* (no hard threshold). Keep it **soft-but-procedural**: a clustering *loop* whose *match test* is a calibration-dependent judgment — not a crisp similarity-threshold algorithm. This is the precise middle the foil's pressure locates.

### Constraint Manipulation (both)
- **REMOVE the goal** → individuation loses its resolution → undecidable (confirms goal-relativity is the decidability source).
- **ADD "individuation must be a crisp algorithm (hard threshold)"** → breaks (the match judgment is irreducibly semantic; a hard threshold mis-merges/mis-splits) → confirms soft-but-procedural is correct.

### Lens Shifting
Shift to "routelister as a cataloger" (FRBR lens): individuation becomes a *routine cataloging judgment* (is this a new work or a new manifestation of an existing work?), goal-relative to the catalog's purpose. Under this lens the "undecidable" fear evaporates — catalogers do this daily. Strongest support for P2's decidability.

## Output — The Mechanism + Foils (for Critique)

**THE CONCEPT-LISTING MECHANISM:** **sweep → individuate → frame.**
- **Sweep:** perceive the goal-relevant territory (surfacing-style traversal; `perceive-by-enumerate`).
- **Individuate (online clustering):** maintain a running set of concept-identities; for each swept item, test it against existing identities via **within-concept signals** — *shared referent* / *manifestation-of* / *shared goal-role* (different: *distinct referent-or-role* / *separately-routable*) — and attach it to a matching identity or start a new one. Under uncertainty, **lean-to-split** (start a new identity), because over-merge hides a concept (unrecoverable) while over-split lists a near-duplicate (visible, mergeable). The match test is a **soft judgment** (calibration-dependent), the clustering is a **procedure** — *soft-but-procedural*, not a hard-threshold algorithm. Individuation is **decidable because goal-relative** (the "undecidable in general" worry was a universal-partition scope error), is the **relational sibling of concept-admission**, and is **incremental** (depth runs re-individuate; converges at a fixpoint). It is a *mature, tractable practice* externally (entity resolution; library-science FRBR's Work↔Manifestation).
- **Frame:** cast each identity as a typed prescriptive route (grain × kind × engagement-type, `18-17`).
**SCOPING:** identity-resolution + goal-bias + convergence (no-new-identities) + workspace-overload frontier-flag.
**OT0:** the concept-listing HOW is now **DEFINED as a mechanism** (linchpin resolved); residue = the structural schema (the running identity-set = the cross-run index) + inherent calibration-softness.

**Foils for Critique:** F1 (drop-individuate=/surfacing) KILL, F2 (undecidable) KILL, F3 (no-scoping) KILL, F4 (lean-to-merge) KILL, F5 (still-undefined/non-answer) REFINE, F6 (over-formalized) REFINE→soft-but-procedural. Critique: adjudicate F2 (decidability) + F6 (soft-but-procedural — does OC over-formalize?) + the self-reference.
