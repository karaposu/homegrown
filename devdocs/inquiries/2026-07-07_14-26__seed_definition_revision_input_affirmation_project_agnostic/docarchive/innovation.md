## Q2 — THE GATE (core-3×, single center)

### Pass 1 — Combination + Lens-shifting: the informativeness-filter

Combine the gate with the harness's own two-part quality architecture (`evolving_quality_assetment_component.md:9-14`: Improvement Detection + Regression Detection). What emerges is not two gates but **one filter with two doors**: the gate asks *"did this extract change your epistemic state about something that matters?"* — and there are exactly two ways for that to be true:
- **The novelty door (improvement):** you learn something the project doesn't yet have (a missing component, a new mechanism, a new frame). This is the old gate — "connects to something un-owned."
- **The confidence door (regression):** you resolve a real uncertainty about something the project already has (is this design sound? does this hold under pressure?). This is the door the prior gate omitted — the affirmation-seed's home.

**Lens-shift test:** under the "improvement-only" lens, paper 20's affirmation (the typed-everything design is sound) looks like noise — it named nothing new, so the old gate scored it grade-neutral. Under the "informativeness" lens, the same affirmation is signal — it resolved a genuine uncertainty (you weren't sure the philosophy held; now you are), which is decision-relevant ("don't rebuild it"). Same seed; the frame decided whether it was noise or signal. The prior dive had the wrong frame.

**Plain-language name (plain-terminology memory):** the gate is an **"is this news?" filter**. News about what you're missing (improvement) or news about whether what you have is sound (regression). Non-news — agreeing with what you already knew — doesn't pass.

### Pass 2 — Absence-recognition: is it exactly two doors? (anti-proliferation, hard)

Probe honestly for MORE doors — other ways an extract changes your epistemic state:
- **RE-WEIGHT door?** A source makes you realize an owned concept matters more (or less) than you thought. Is this a third door? **Test:** a re-weight is a change in your confidence about a concept's *importance* — which is a confidence-change about something you already have. That's the **confidence door** (regression-family), not a new door. It also lacks its own canon grounding (the harness has no "priority-detection" architecture parallel to improvement/regression). **Verdict: FOLDS into the confidence door. Flagged-not-minted.**
- **CONNECT door?** A source reveals a relation between two owned things. Third door? **Test:** a newly-seen relation is *new knowledge the project didn't have* — that's the **novelty door** (improvement-family: you named something absent, namely the relation). The prior taxonomy's CONNECT development-kind lives here. **Verdict: FOLDS into the novelty door.**
- **Anti-proliferation landing:** the two doors are **canon-forced** (they ARE the harness's own two-part architecture) and absorb the plausible third-door candidates. Minting a third door would multiply the harness's own binary cut without its own grounding — exactly the proliferation the harvest-flavor memory warns against. **Two doors. Others fold or are flagged-not-minted.**

### Pass 3 — Inversion (REQUIRED Piece-Level Inversion) + depth-check

**Invert "generalize the gate (two-halved)" → "DROP the gate — any usable/affirming/unique extract is a seed; the user is simply right, stop adding constraints."**

*Re-defeat (structural, on the harness's own logic):* dropping fails on the **regression-information principle**. Regression detection has value only when the thing checked *could have been broken* — a regression-check on already-known-good code yields zero information (this is *why* `project_north_star.md:61` frames absence-of-failure as a first-class *detection signal*: detection presupposes something detectable). So "any affirmation counts" is false **by the harness's own standard** — an affirmation of the already-certain carries no information. Dropping the gate doesn't honor the affirmation-seed; it **drowns** the real one (paper 20's) in decorative agreement, re-opening `finding.md:47`'s manufactured-seed floodgate. The user's insight (affirmation is real) is met by *opening the confidence door*, not by *removing the doorframe*.

*Depth-check — invert again, to system-level:* "the gate is about novelty" → "the gate is about novelty OR confidence" → (system level) **"the gate is about INFORMATION — does this extract carry information about the project you didn't already have?"** Novelty and confidence-change are not two arbitrary doors; they are **the two directions of information about any system**: information about what's *absent* (improvement/novelty) and information about whether what's *present* is sound (regression/confidence). This system-level statement is why there are exactly these two and why re-weight/connect fold: every epistemic-state-change about a project is either news-about-the-absent or news-about-the-present. The gate is an **information filter**; the two doors are exhaustive because a project has exactly two things to be informed about — what it lacks and what it holds.

*Face-save self-check:* does Pole-B keep a gate just to avoid admitting I was wrong? **No.** It DEMOTES my prior gate ("un-owned") from THE gate to ONE door, and adds the confidence door as co-equal (arguably primary, since the harness makes regression primary). That is a real, line-cited correction — a face-save would leave the gate unchanged and dismiss the affirmation-seed. Neither cave (Pole-A) nor face-save. **Landing: two doors, unified as an information filter.**

### Constraint-manipulation + Domain-transfer (supporting)

- **REMOVE the "un-owned" constraint:** what's left of the gate? Not nothing — "informativeness" remains (did this carry information?). This confirms "un-owned" was a *special case* of the real constraint (informativeness-about-the-absent), not the constraint itself. **ADD the affirmation-door's guard:** "the affirmation must resolve a *real, previously-open* uncertainty" — this is the confidence-door's admission test, the exact analogue of "un-owned" for the novelty door.
- **Domain-transfer (software regression testing, native source):** a unit test that only ever passes — that covers code which was never at risk — is *redundant* and gets deleted in a healthy suite; a test earns its keep by covering a path that *could* break. Transfer: an affirmation-seed earns its keep only by resolving an uncertainty that *could* have gone the other way. Decorative agreement is the always-passing test — redundant. This is the same principle as the regression-information point, reached from a different domain → **mechanism-independent convergence** (robustness signal for the two-door gate).

## Q4 — THE TYPING AXES

### Develop the affirmation-seed's development-action (decision-vs-label, hard)

An inspiration-seed develops into build / mechanism / frame / refine / connect (the prior 5 kinds re-home here as inspiration's sub-structure). What does an **affirmation-seed** develop into? Candidates: CITE (use as evidence) / RAISE-CONFIDENCE (promote a hunch) / GREEN-LIGHT (unblock a decision) / STAND-DOWN (cancel a planned rebuild — paper 20's "don't rebuild the typed design").

**Decision-vs-label test, applied hard:** are these four distinct development-actions, or one action with four targets? They are all **"spend the raised confidence"** — the differences are only in *what you spend it on* (evidence / a hunch's grade / a blocked decision / a planned rebuild). That is not four development-kinds; it is **one light action** (spend-the-confidence-on-the-decision-it-unblocks) with different objects. **Do NOT mint four affirmation-development-kinds** (proliferation). 

**This is itself the key structural finding for Q4:** the development-action axis has *rich* branching under the inspiration pole (five real kinds) and is *nearly degenerate* under the affirmation pole (one light action). An axis that only structures one of the two function-poles **cannot be the primary cut** — which is exactly why FUNCTION is primary and development-action is a sub-typing under inspiration.

### Test the CONTENT axis (idea / concept / analogy)

Does content change a development-action *independent of function*? Test the analogy: an analogy-seed can do affirmation-work ("this pattern works in domain X, so ours is sound") OR inspiration-work ("this pattern from X suggests a new mechanism"). So content is **orthogonal to function** (the same content serves either function) — a real descriptive axis (what the seed IS). BUT: does an analogy-affirmation develop *differently* from an idea-affirmation? Barely (both spend confidence). Does an analogy-inspiration develop differently from an idea-inspiration? Slightly (an analogy may add a "map it across" step). **Decision-vs-label verdict:** content is a real *descriptive* axis but **weak on changing a development-action** — it *describes*, it doesn't *route*. **Landing: keep content as an orthogonal, descriptive, PROVISIONAL axis (example-thin), explicitly marked as not-action-routing** — the weakest of the three, held lightly. Do not over-invest to be tidy.

### Piece-Level Inversion (REQUIRED) — function-primary → development-primary

**Invert "FUNCTION is primary" → "development-action is primary; calling function primary over-builds a user-deferred axis (proliferation)."**

*Re-defeat:* (a) the two function-poles are **canon-forced** (they fall out of the harness's two-part architecture) — not arbitrary flavors, so naming them isn't proliferation; (b) the full function-*enumeration* IS deferred (honored — I mint only the two canon-forced poles, "etc" stays open per the user); (c) development-action **can't be primary** because it barely applies to affirmation-seeds (one degenerate action) — a primary axis must structure the whole space, and development-action structures only the inspiration half. Function passes the decision-vs-label test (inspiration→build vs affirmation→spend-confidence are genuinely different actions); development-action fails as a *primary* cut (non-uniform coverage). **Landing: function primary (two poles), enumeration deferred, development-action re-homed under inspiration, content orthogonal-provisional.**

## Emergent Probe — does the two-halving reach the whole ladder? (hold honestly, flag scope)

**Extrapolation:** if the SEED gate is two-halved, and the seed gate descended from the harvest's **import test**, is the import test also two-halved?

**The honest, checked answer (anti-inflation catch):** I was about to claim "the import test is improvement-only and needs a new regression-half." IS affirmation-of-the-uncertain. So the two-halving is **not a new invention**; it was **always latent** in the import test (NAMES = the novelty door, RESOLVES = the confidence door). What went wrong is narrower and more precise: the prior *seed-definition* collapsed the import test's two clauses into improvement-only ("connects to something the harness does not already own," `finding.md:57`) — it **inherited only the NAMES clause and dropped the RESOLVES clause**. 

**This STRENGTHENS the whole revision:** the generalized gate isn't bolting a new half onto the concept — it is **restoring the RESOLVES clause the seed-definition had dropped**. The import test was two-halved all along; the seed-def under-inherited it.

**Import-test the emergent (does it change a decision?):** YES, but a *future* one — it means (i) the two-halving should be made *explicit* across the harvest ladder (the RESOLVES clause named as the regression-door everywhere), and (ii) the `non-sycophancy-both-ways` memory's import test could be stated in its two-door form. **Scope:** this dive revises the SEED definition, not the import test or the ladder. **Disposition: RESEARCH FRONTIER + RE-TEST TRIGGER** — flagged for a future dive (make the ladder's two doors explicit) and as a re-test note on the import test's phrasing; explicitly **NOT built here**, and explicitly **not an over-claim** (the halves already exist; only their explicitness is missing).
