### 6. The lazy pair — §3.6 protocol text (slot-ready)

> **Re-runs (the lazy pair).** A sweep-map is static once emitted — history, never edited (the Dived ✓ column depends on this). Evolution happens by re-running the sweep on the same practice: **on any re-run, create `_sweep.md` beside the maps if absent**, seeding its identity-set from the prior map's index — **including its dived column, seeded from the prior map's ✓s with per-run provenance (`dived @run1`)** — then load it, and emit a NEW map (`paradigm_sweep_v2.md`, `_v3`, …). In the index that travels forward: enrich entries with what dives taught; **stale-flag** mis-individuated or dissolved families with a reason — never delete, never renumber. `stale(reason)` values appear only on run-≥2 maps, authored at emission. **Every new map's ✓ column is authored empty** — per-run engagement lives on the map; cumulative dive-history lives in the index. Prior maps stay untouched. `_sweep.md` carries only the family-identity-set (family · status · grounds-pointer · dived · first-seen/last-touched) and an invocation log — no process state.

**Why lazy:** today's routelister audit found the cumulative `_route.md` machinery fresh-only across all 20 wild maps — an index no second run loads is a copy of the map's own table. The semantics are committed now; the file is born at second contact.

**Why instruments sit at §2, before Process.** The mandated inversion ("runners want Process first; appendix the instruments") lost at the house letter: both sibling references put their component/type-system section before Process, because process text consumes the components' vocabulary — and an appendix signals optional, the wrong register for a single source of truth the hook will cite.
