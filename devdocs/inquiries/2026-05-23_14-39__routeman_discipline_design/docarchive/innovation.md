#### Mechanism work

### P2 — Endgame fit (meta-decision piece)

#### Principal candidate

**Endgame fit (3 functions, committed at sensemaking SV6):**

**EF-1 Enumeration-first preserves multi-head compatibility.** Per `project_end_goal_loop_architecture` memory + finding 57: multi-head architecture (Level 3+ autonomy) consumes enumerations because each parallel head picks its own direction. Routeman's "enumerate all possible next moves" verb preserves this. Selection-first specs become awkward under multi-head; routeman's design avoids this awkwardness.

**EF-2 Auto-vs-judgment split provides L0-L4 positioning.** Per `docs/desc.md` + canonical /navigation §"Auto-Derivable vs Human-Judgment": at L0, human handles all 4 judgment types + reviews 12 auto types; at L3+, system handles all 16. The 12/4 partition (inherited via L-i9) is the autonomy-ladder anchor.

**EF-3 Rename-as-design-act demonstrates corpus-hygiene autonomy.** *(Novel-to-this-inquiry — flagged for Critique adversarial testing.)* The corpus-baggage problem (motivating the rename) is a maintenance burden that grows as the system scales. Rename-as-design-act with structural grounding is a maintenance pattern for long-running self-improving systems. The system's ability to refactor its own corpus is itself an autonomy indicator (per desc.md's "spontaneous attention" — noticing what should change unprompted).

#### Mechanism work

**Extrapolation (Generator):** extrapolate the trends shaping the endgame.
- *5-year trend 1:* multi-head architecture matures → enumeration-first specs become MORE load-bearing → EF-1 strengthens.
- *5-year trend 2:* autonomy ladder progression L0 → L4 → routeman's auto/judgment split shifts (auto side handles more types) → EF-2 strengthens.
- *5-year trend 3:* corpus growth → cognitive-load of stale references compounds → EF-3 strengthens.

All 3 endgame functions strengthen over time. Routeman is more end-goal-aligned in the future than today.

**Combination (Generator):** combine EF-1 + EF-2 + EF-3 to find emergent value.
- EF-1 (enumeration-first) + EF-3 (corpus-hygiene) → at multi-head + corpus-clean state, routeman becomes a discipline that maintains parallel-head coordination via clean enumerations. Corpus hygiene reduces inter-head confusion when heads consume each other's outputs.
- EF-2 (L0-L4) + EF-3 (corpus-hygiene) → at higher autonomy, the system itself maintains corpus hygiene. Routeman is a discipline-level demonstration of this capability.
- **Emergent value:** routeman as "a discipline that exercises the project's capacity to refactor itself." The rename methodology is a meta-endgame demonstration.

#### Principal candidate

**Absence Recognition (Generator):**

*Redesign-level absence:* what would exist if routeman's failure-mode framework were designed from scratch?

- **L2-C — Auto-vs-Judgment Calibration Drift.** *Recognition:* the F5 12/4 split is no longer calibrated to the project's autonomy level. *Why-erodes-identity:* humans handle types the system should now handle (over-conservative) OR system attempts judgment-required types prematurely (over-aggressive).
