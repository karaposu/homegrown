## Phase 2 — Generate (7 mechanisms × 3)

### 1. Lens Shifting (Framer)

- **1G — flight-hours lens.** Pilot training doesn't perfect the simulator before flying; it logs **supervised flight hours**. Recorded turns = flight hours; loop-polish = simulator-tweaking. The license (autonomy) comes from logged hours, not simulator fidelity. Feeds the recommendation's framing and the first-turns bar.
- **1F — dashboard lens (focused on the signal-set).** The signals presented as a tiny instrument panel: each signal = name + where-it's-read + current reading (firing/quiet) + what-would-change-it. One screen, glanceable, consultation becomes real instead of aspirational.
- **1C — debt-collector lens (contrarian).** Two of the "evidence the loop is fine" items are actually **unpaid debts** (the never-built checker; the never-written pre-registration file). A switch that walks away from debts is flight, not strategy. Adopted as constraint: **the two debts travel WITH the switch** — they are not optional exceptions but obligations that ride along (both serve both tracks).

### 2. Combination (Generator)

- **2G — observations habit × turn-invariant → the closing line.** One end-of-run habit, not two: every run closes with one line that serves both channels — an observation (if any) into `improvement_observations.md` AND, when a next route is chosen, the selection + rationale into traversal memory. One sentence of friction total; both starving data streams fed.
- **2F — control-loop home × existing canon → the Allocation Rule subsection.** The standing rule lives INSIDE `docs/canon/sustained_traversal_loop_of_loops.md` as a short "The Allocation Rule" section — the path-to-achievement's natural sibling; no new doc; it also UPGRADES the north star's "two complementary tracks" passage (which says "neither replaces the other" but gives no signals) by reference.
- **2C — switch-back signals × the thesis test-set → severity grades.** A switch-back signal is not one thing: **fix-grade** (a consumer failure or recurring failure-mode → demand-driven repair session) vs **redesign-grade** (the baseline program, when run, shows the loop LOSING to plain prompting on a task class → not polish, a redesign inquiry). Graded reversal prevents both over- and under-reaction.

### 3. Inversion (Framer; depth-checked)

- **3G — the throughput inversion (on the seed's premise).** Belief: "the loop is the core, so the better it is, the better everything is." Invert at system level: **excess loop quality can hurt the system** — polish that adds ceremony raises turn cost → fewer turns → less calibration data → slower climb → later instruments. Quality has a DIRECTION: polish that removes friction helps the whirl; polish that adds ceremony starves it. Multi-axis check — existence: is turn-cost rising? (~28 min for a 6-discipline run today; watchable). Identity: what IS loop improvement? — friction-removal and defect-repair, not accretion. **Yields a new watch-signal: the turn-cost trend.**
- **3F — focused (first turns).** "First turns should target the most important routes" → invert: first turns should be **cheap and low-stakes** — their purpose is habit formation and calibration data, not optimal navigation; a bad early selection honestly recorded is GOOD data (it trains the future Selector). Resolution: turn 1 doesn't need to be wise; it needs to be RECORDED. Removes the perfectionism blocker.
- **3C — contrarian (the pause).** "Spec-refinement pauses" → invert: what if refinement is the operator's joy engine, and pausing it drains the whirl's energy source (the sustainability bar)? Resolution: the pause targets OBLIGATION-refinement (polishing because "it should be better"), not curiosity. If a discipline idea genuinely excites, run it — knowingly costed as a session, and soon data-fed by the closing-line habit. **Pause-as-default with an honest joy-exception.** *Flagged as a RE-TEST item for Critique: confirm the joy-exception preserves the anti-data-starved-polish intent of sensemaking's recommendation without quietly restoring polish-as-default.*

### 4. Constraint Manipulation (Framer; both directions)

- **4-ADD (generic).** **The one-screen constraint:** the entire dashboard must fit on one screen. Brevity forced; consultation realistic.
- **4-ADD (focused).** **The consultation trigger:** re-read the dashboard after every ~5 completed inquiries OR whenever any switch-back signal fires — self-consulting cadence without a calendar.
- **4-REMOVE (generic).** Remove "minimal SUSTRALL" as the threshold → nothing coherent replaces it; the threshold IS the instrument-arrival point. Removal experiment confirms it is load-bearing. Recorded.
- **4-REMOVE (contrarian).** Remove the human from signal-reading (auto-compute the dashboard) → premature (judgment still needed; no checker exists) — but adopted as a DESIGN constraint: **write every signal greppable** (file-locatable, count-based where possible) so mechanization is a later edit, not a rewrite.

### 5. Absence Recognition (Generator; both levels, bidirectional)

- **Patch-level absences:** (a) the threshold's exact content for THIS decision — **minimal SUSTRALL = Tier 1 (memory artifact, turn-invariant, the eyes' habit, ~10 recorded turns) through Tier 2 (Selector graduation)** — that is where loop-quality becomes knowable; Tier 3+ is not required for the knowing. (b) A name for the standing rule — candidates: *the Allocation Rule* (plain), *the Bottleneck Dashboard* (the instrument half). (c) The newest runner's own state: `/aMVLw` is N≈2 runs old — **watch-item: aMVLw needs ~5 more runs before its own refinement is even data-possible** (refining it now would be guessing about a thing that hasn't run).
- **Redesign-level.** Designed from scratch, "when do I stop improving X?" generalizes to a reusable pattern for ANY component: **consumer-contract satisficing + instrument-gap routing + both-direction signals.** Named: **the good-enough protocol** — a future methodology entry (proposed, not built here).
- **Bidirectional (already-present).** Canon already has the rule's embryo: the north star's two-tracks passage. The Allocation Rule is its upgrade-with-signals, not a new invention — promotion-with-lineage again.

### 6. Domain Transfer (Generator; native source included)

- **6-native (software).** The **test-pyramid/CI wisdom**: nobody perfects unit tests before writing integration tests — integration tests REVEAL which unit-level defects matter. Turns are the loop's integration tests.
- **6-different (manufacturing).** **Toyota's andon cord**: the line RUNS by default; it STOPS when a defect signal fires; improvement happens at the stoppage, demand-driven (kaizen). This is the recommendation's exact shape with a fifty-year-old name: **climb by default; stop-and-fix on signal.**
- **6-different (science).** **Instrument-led discovery**: Galileo didn't perfect lens theory before pointing the telescope — USE revealed which lens defects mattered (chromatic aberration was discovered by observing). The first turns will reveal which loop defects matter — pointing the instrument beats theorizing about its flaws.

### 7. Extrapolation (Generator)

- **7G — the rule's growth path.** Six months out: signals computed mechanically (checker-era); the dashboard folded into traversal memory's standing report; the allocation question itself becomes an ORCHESTRATOR decision. **Today's manual Allocation Rule is the L0 seed of the L3 orchestrator's self-allocation policy** — the staircase pattern applied to the rule itself. Write it so it can graduate (greppable signals; explicit triggers).
- **7F — the closing-line habit compounds.** One line × ~100 runs/year ≈ a hundred-line failure-and-selection data stream per year — the input that makes ALL future discipline-refinement data-driven. The cheapest compounding asset in the project.
- **7C — the pause's rot risk.** If refinement pauses for months, do specs rot under substrate drift (new model versions behaving differently under the same prose)? Mitigation already standing: the recurrence switch-back signal catches behavioral drift as failure-mode recurrence; canary snapshots exist for revert. The pause is drift-safe. Recorded.
