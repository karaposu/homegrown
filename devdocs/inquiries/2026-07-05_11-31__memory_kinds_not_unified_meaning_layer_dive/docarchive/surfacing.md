## PART A — The Paper's Taxonomy (FACTs, quoted where load-bearing)

- **A-0 — THE SEED, verbatim.** *"The concept of memory is not reducible to a single unitary phenomenon; instead, evidence suggests that it can be subdivided into several distinct but interrelated constituent processes and systems."* (line 123) The paper's whole structure enacts this: it divides memory on **multiple orthogonal axes at once**, not one. [core]

- **A-1 — Axis 1: by ACCESS (consciousness).** Explicit/**declarative** (*"can be recalled consciously… facts and events"*) vs implicit/**non-declarative** (*"unconscious forms of learning such as skills, habits, and priming… does not involve conscious recollection"*). [core]

- **A-2 — Axis 2: by DURATION.** **Working memory** = *"a unique transient active store capable of manipulating information"* — transient, active, in-the-moment — vs **long-term** (declarative + non-declarative). Working memory is not itself a store of record; it's a *manipulation workspace*. [core]

- **A-3 — Axis 3: by CONTENT (within declarative).** **Episodic** = *"recollection of personal experiences… detailed information about events that happened in one's life"*; retrieval feels like **"remembering."** **Semantic** = *"knowledge stored… as facts, concepts, ideas… general world knowledge"*; retrieval feels like **"knowing."** (line 466–470) The distinguisher is *event-with-context* vs *context-stripped fact*. [core]

- **A-4 — Non-declarative is itself plural.** *"Non-declarative memory is a collection of different phenomena with different neural substrates rather than a single coherent system"* (line 523) — procedural (skills/habits), priming, associative (conditioning), non-associative. Even the "kinds" have kinds. [supporting]

- **A-5 — Memory is STAGES, not just kinds (orthogonal division).** *"Memory is a multifaceted cognitive process that involves different stages: encoding, consolidation, recovery, and reconsolidation."* (line 74) **Encoding** = transform input into a storable representation. **Consolidation** = *"stabilization and integration of memory into long-term storage."* **Retrieval** = *"accessing, selecting, and reactivating or reconstructing"* (note: reconstructing, not verbatim read). **Reconsolidation** = *"stored memories, when reactivated, enter a fragile or liable state and become susceptible to modification or update… memory is not static but a dynamic system."* (line 111–115) [core]

- **A-6 — Consolidation has TWO kinds.** **Cellular/synaptic** = short-term local stabilization; **system** = *"memories are gradually transferred to and integrated with cortical neurons"* — hippocampus → neocortex over time. [core — system consolidation; peripheral — cellular, being implementation]

- **A-7 — THE KIND-CHANGE (load-bearing).** Consolidation into neocortex *"involves a loss of specific finer details, such as temporal and spatial information… an evolution from episodic memory toward semantic memory, which consists mainly of gist-based facts."* (line 856–861) **A memory changes KIND over time: a specific event becomes a general fact.** [core]

- **A-8 — SCHEMA integration.** System-consolidation rate *"depends on an individual's ability to relate new information to existing networks… known as 'schemas.'"* The mPFC *"integrates this information with the existing knowledge."* New memory is bound into the existing web, not filed standalone; prior knowledge speeds it. [core]

- **A-9 — The EPISODIC BUFFER (binding workspace).** *"A multidimensional but essentially passive store… provides a crucial link between the attentional central executive and the multidimensional information"* — binds features from perception + long-term memory into integrated chunks. An integration bridge between the transient and the durable. [supporting]

- **A-10 — Offline consolidation + REPLAY + downscaling.** Consolidation happens *offline* (sleep): *"the brain selectively reactivates newly encoded memories during sleep, which enhances and integrates them into the network of pre-existing long-term memories."* Plus synaptic homeostasis: sleep *downscales* to *"avoid saturation of resources."* [supporting — the offline-reorganization idea is core; the neural mechanism is peripheral]

- **A-11 — TAGGING (importance-marking).** Synaptic/behavioral/emotional tagging: a weak memory is stabilized if marked important (by a nearby strong event, or emotional arousal) — *"mark experiences as necessary, thus enhancing… transformation from transient into more permanent forms."* Importance is a first-class signal that decides what consolidates. [supporting]

- **A-12 — WHY no unified memory (the argument).** Each kind has a distinct substrate, distinct access, distinct duration, distinct failure mode — dissociable (lesions knock out one kind, spare others). A single store can't be transient-and-durable, conscious-and-unconscious, event-detailed-and-gist-general at once. The divisions are *functional necessities*, not taxonomic tidiness. [core — inference from the paper's structure, strongly grounded]

## PART C — The Mapping (possibility-items, three directions + reverse)

### HAVE — paper kind ↔ a piece we already named
- **C-H1 — Episodic ↔ our inquiry/selection records.** [core] Findings + the travel-log candidate ARE episodic memory: events with context ("what was visited, selected, why, with what outcome" = B-1 is literally episodic — event + rationale + outcome). Retrieval = "remembering." Strong match.
- **C-H2 — Semantic ↔ our canon docs.** [core] Canon = gist-based facts, context-stripped, the project's "knowing." A near-exact match to semantic memory.
- **C-H3 — Working memory ↔ the in-traverse session context.** [supporting] A single traverse's live context (its scratchpad while solving) is working memory — transient, active, manipulation, discarded at conclude. We have it; we've never named it as a memory KIND distinct from traversal memory.
- **C-H4 — Retrieval-as-reconstruction ↔ warm-session judgment.** [supporting] Our reads aren't verbatim fetches; a warm session reads a label and reconstructs relevance (00-47's offer-menu). Matches A-5's "reconstructing."

### LACK — paper kinds we plausibly need but have no concept for
- **C-L1 — CONSOLIDATION as a distinct stage [CORE — likely the elegance].** [core] We have encoding (File/mark-done = raw append) and retrieval (pull/enumerate), but **no consolidation stage** — the offline reorganization that integrates raw records into schema-linked, gist form. Everything we call a "fix" (distillation B-6; staleness worry; mark-done reconciliation) is really the *missing consolidation stage* of a memory lifecycle. Reframes patches as one named process.
- **C-L2 — The episodic→semantic KIND-CHANGE [CORE].** [core] We have no concept of a memory *changing kind*. Yet the project already does it: inquiry records (episodic) get distilled into canon (semantic) — A-7 exactly. We've been doing episodic→semantic consolidation without naming it, so we treat canon-writing as unrelated to memory maintenance. Naming it unifies "distillation," "canon-authoring," and "index summarization" as one transition.
- **C-L3 — RECONSOLIDATION [CORE].** [core] Today's own correction pass (re-opening the 00-21 finding, marking it labile, re-storing it corrected) IS reconsolidation (A-5) — a reactivated memory becomes editable and re-stabilizes. We have no memory concept for it; we call it "editing a finding." Naming it makes correction a first-class memory dynamic, not an exception.
- **C-L4 — ENCODING vs raw storage [supporting].** [supporting] File just appends the direction verbatim; there's no *encoding* step (transform into a storable, matchable representation). The paper separates them; our "double-filing/dedup" gesture at encoding but it's unnamed.
- **C-L5 — SCHEMA-binding at write time [supporting].** [supporting] A-8: new memory binds into the existing web, and prior knowledge speeds consolidation. Our File appends *standalone*; nothing binds a new direction into related existing ones (the ODI's "link" by-product is the seed, unnamed as schema-binding).
- **C-L6 — IMPORTANCE-tagging as a consolidation gate [supporting].** [supporting] A-11: what consolidates is what's *tagged important*. We have priority markers on routes, but they're not wired to a consolidation decision (what to keep vs let fade). The paper says importance should *drive* the kind-transition.

## Clusters / The Emerging Shape

- **Cluster 1 — Our "traversal memory" is monolithic where the paper is layered [core].** We have one flat accumulate-store split on ONE axis (taken/not-taken). The paper divides on THREE axes (access / duration / content) AND across STAGES (encode / consolidate / retrieve / reconsolidate). The missing sophistication the user senses is real and locatable.
- **Cluster 2 — The likely elegance: memory is a LIFECYCLE with kinds at each stage, not a store [core].** working (in-traverse) → episodic (inquiry records: event+why+outcome) → semantic (canon: gist facts) — moved by CONSOLIDATION (distillation, offline, between traverses = the navigation session's territory), with RECONSOLIDATION (correction passes) re-opening stored memories, and OPTION-memory as a distinct prospective face we uniquely have. [inference — the load-bearing candidate for sensemaking to test]
- **Cluster 3 — Our "fixes" are one named stage in disguise [core].** Distillation, staleness-pruning, mark-done reconciliation, canon-authoring, index-summarization — all fragments of the single **consolidation** stage (C-L1/C-L2). Naming it collapses scattered patches into one concept. [inference]
- **Cluster 4 — The kind-map explains past intuitions [supporting].** Why the ODI felt novel (C-R1: off the human map); why canon-writing felt separate from memory (C-L2: unnamed kind-change); why the index "goes stale" (C-L1: no consolidation stage, only encoding). [inference]
