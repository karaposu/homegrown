**Key Insights**
- K1. **The import test (the discipline of this whole inquiry):** an import is *real* iff it (a) NAMES something we already do but hadn't named, or (b) RESOLVES a confusion we already had. Merely attaching a biological label to an existing thing = decorative. This test is the guard against both over-fit and dismissal.
- K2. Under K1, the strong survivors are **consolidation** (names the offline reorganization we do unnamed) and the **episodic→semantic kind-change** (names inquiry→canon as one operation). Both pass (a); consolidation also passes (b) — it resolves the "why does the index go stale?" confusion.
- K3. The lifecycle reframe re-organizes the five commitments rather than re-labeling them: they turn out to describe **different stages/kinds**, not one thing — that's a structural re-seating, not a rename.
- K4. Option-memory is genuinely off the human map (surfacing C-R1) — so the reframe must *extend* the paper, not just adopt it. This is the honesty guard: our domain is not a subset of the paper's.

**Structural Points**
- S1. Our five commitments, re-seated by kind/stage: SUSTRALL "visited/selected/why/outcome" = the **episodic** kind (event+context+rationale+outcome). Canon = the **semantic** kind (gist). In-traverse context = **working** memory. Option-memory = a **prospective** face (ours, extra). Selection-record = episodic. So "traversal memory" was never one thing — it was a *family* named singularly.
- S2. READ≠MEMORY re-seats cleanly: the writes are *encoding + consolidation*; the reads are *retrieval*. The stage-model explains WHY read≠memory (retrieval is a stage that consumes, doesn't constitute).
- S3. Consolidation is *offline and between-traverses* — which is exactly the navigation-session/between-inquiry territory of the prior unload finding. The dive connects.

**Meaning-Node**
- **A memory has a life, not just a location.** The unification error wasn't "one store" spatially — it was treating memory as a *thing* rather than a *process with kinds at each stage*.

### A3 — Is consolidation-as-a-named-stage the single highest-value import?

## Phase 5 — Conceptual Stabilization

### SV6 — Stabilized Model

**The meaning-layer answer: our "traversal memory" was one word for a family, and the missing sophistication is that memory is a lifecycle with different kinds at each stage — most importantly a stage we never named: consolidation.**

1. **The reframe (the elegance).** Stop treating traversal memory as *a store* and treat it as *a process with kinds*. Our five commitments were never one thing; they were positions in a lifecycle:
   - **Working memory** — a single traverse's live in-context scratchpad (transient; discarded at conclude).
   - **Episodic memory** — the inquiry/selection records: *what was visited, selected, why, with what outcome* (event + context + rationale). This is exactly SUSTRALL's definition — which turns out to define *one kind*, not memory-in-general.
   - **Semantic memory** — the canon: context-stripped, gist-based, reusable facts ("knowing").
   - **Option memory (prospective)** — roads noticed-but-not-taken (the ODI). This one is *ours beyond the paper* — human memory has no dedicated store of set-aside intentions; it's why the ODI felt novel.

2. **The load-bearing import: consolidation is a real stage we do unnamed.** Between the episodic records and the semantic canon sits an offline reorganizing pass that strips detail, extracts gist, binds into existing knowledge, and prunes the spent. We have been performing it piecemeal and calling the fragments by five different fix-names — *distillation, staleness-pruning, mark-done, canon-authoring, index-summarization*. They are one process: **consolidation**. Naming it does three things at once — it unifies the patches, it explains a confusion we already had (the index "goes stale" precisely because we had encoding and retrieval but no consolidation stage), and it lands exactly on the between-traverse territory the prior finding was trying to unload. That triple is why this is the meaning-layer breakthrough, not a relabel.

3. **Canon-authoring IS memory-consolidation** — literally, not by analogy. A dated episodic record ("on 2026-07-05 we found X because Y") becoming a timeless semantic fact ("X") is the paper's episodic→semantic transition on three structural counts: lossy context-stripping, episodic→semantic direction, and offline schema-binding. The project has been consolidating memory all along (inquiries → canon) without recognizing canon-writing as memory maintenance — which is why it felt like a separate craft.

4. **Reconsolidation names what we did today.** Re-opening a stored finding (the 00-21 correction), making it labile, and re-storing it corrected is the paper's reconsolidation — *"stored memories, when reactivated, enter a fragile state and become susceptible to modification."* We had no memory-concept for it; we called it "editing." Named, it makes correction a first-class memory dynamic.

5. **What does NOT import (the honesty both ways).** The neural substrate, and the *conscious/unconscious* framing of explicit vs implicit, are decorative for us — kept, at most, as a weak functional analogy (ambient warming context ≈ implicit; deliberate pull ≈ explicit), not a load-bearing kind. The test that separated the real from the decorative: an import counts only if it **names something we already do** or **resolves a confusion we already had** — otherwise it's a pretty label. Consolidation, the kind-change, the working/episodic/semantic distinction, retrieval-as-reconstruction, and reconsolidation pass; the biology fails.

6. **The bound (meaning layer, as instructed).** This run fixes what the kinds ARE. Three further meaning-nodes are real but their *design* is deferred to a later structural inquiry: **encoding** (transforming a raw direction into a matchable representation), **schema-binding** (linking a new record into related existing ones at write time), and **importance-tagging** (letting priority gate what consolidates vs fades). Named here; specified later.

**Guards held:** Clean-Resolution-Trap — every ambiguity keeps its strongest counter (A1 retains the domain-gap as a real bound that kills the biology imports; A4 retains "surface coincidence" and defeats it with three structural matches). Anchor-dominance both ways — "elegant lifecycle" did NOT halo into "total breakthrough" (much is decorative/deferred; the win is one stage + a reframe); "different domain" did NOT halo into "nothing transfers" (K1 rescued the functional imports). Self-reference — adjudicated against the paper's quoted text and our own commitments, not against a prior verdict; the user's wanted-elegance was earned via K1, not granted.

**SV1→SV6 delta:** SV1 guessed "lifecycle, concentrated on consolidation." SV6 delivers the import test (K1) that makes the selection non-arbitrary, the re-seating of all five commitments into kinds/stages, the strong committed claim that canon-authoring literally IS consolidation, the naming of today's correction as reconsolidation, the explicit quarantine of the biology, and the meaning/structural boundary.

**Highest-value output:** **consolidation** — the one memory stage the project performs constantly (inquiries→canon, index-distillation, mark-done) but never named, whose absence-as-a-concept is why our memory work felt like scattered fixes rather than one elegant process, and which sits exactly on the between-traverse layer the era must build.
