### ★ GQ1 / P2 — the aspect-depth method (THE load-bearing gate)
**Prosecution (strongest kill):** even the new-anchor case folds. The owned pre-pass says "interrogate the source against each canon facet." A skilled operator interrogating a rich source richly WILL engage its dynamics; the new anchor (shape-definition) emerges from that. The aspect-kit adds no new instruction — it's implicit in "interrogate richly."
**Defense (strongest keep):** the owned instruction is **anchor-INDEXED** — verbatim "against each canon *facet*." It iterates over EXISTING facets. There was no "shape-definition" facet before p29-S2 *created* it; the instruction cannot iterate over a non-existent facet. Reaching a frame-CREATING aspect requires a **source-INDEXED** instruction — "walk the phenomenon's own aspects (mechanics/dynamics/failure-modes/…)" — which is absent from the owned pre-pass. **a.md is the existence proof:** the user reached p29-S2 by engaging the spider's own define-then-fill dynamic, NOT by interrogating a shape-definition facet that didn't exist.
**Collision:** the prosecution conflates "interrogate against facet X" (anchor-indexed, verified in the source text) with "engage the phenomenon" (source-indexed). They are different instructions. BUT the prosecution wins a **narrower** point: where a source's aspect DOES map to an existing anchor, the owned instruction reaches it — so the delta is bounded to the NEW-ANCHOR case.
**Verdict: SURVIVE (sized) + constructive sharpening.** Aspect-depth is a real added instruction — a **source-indexed aspect-walk** complementing the owned **anchor-indexed interrogation** (the source-driven and anchor-driven halves of expansion). Bounded to the new-anchor / frame-creating frontier (= the 19-14's own open depth-frontier); folds into the owned move for existing-anchor aspects. **The gate BIT:** it confirmed the bounding (a real contraction — not "the depth lever") AND sharpened the distinctness to the anchor-indexed-vs-source-indexed framing, which is airtight where the innovation's "source-driven vs anchor-driven" was looser. D1 ✓ (source-indexed instruction genuinely absent from owned). D2 ✓ (owned text quoted). D4 ✓ (sized).

### GQ2 / P2-framing — aspect-kit vs sensemaking-perspectives
**Prosecution:** the aspect-kit ≈ sensemaking's perspective-checking (both enumerate dimensions to engage) → redundant with an owned discipline.
**Defense:** perspectives = the ANALYST's viewpoints (technical/human/risk — how *I* look); aspects = the PHENOMENON's own structure (its dynamics, its failure-modes — how the *thing* works). Applying "the risk perspective" ≠ engaging "how the web fails." And sensemaking-perspectives analyze the INQUIRY, not source-expand a thin SOURCE — different job.
**Collision:** one genuine overlap (risk-perspective ≈ failure-mode-aspect), but the kit is source-STRUCTURAL vs perspective-ANALYTICAL. Distinct.
**Verdict: SURVIVE + constructive.** Keep the aspect-kit; frame it explicitly as **source-structural (the phenomenon's own dimensions)** to prevent the fold; note the one honest overlap.
