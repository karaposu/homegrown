## Finding

### What Horizontal Dive + Vertical Refinement + Synthesis is, briefly

Because this finding is about the broader class that Horizontal Dive + Vertical Refinement + Synthesis belongs to, it is read most clearly with a self-contained picture of Horizontal Dive + Vertical Refinement + Synthesis itself in hand. The full articulation lives in the prior finding at `devdocs/inquiries/2026-06-08_12-12__horizontal_dive_vertical_refinement_pattern/finding.md`; this section restates the essentials so the rest of this finding can be read on its own.

Horizontal Dive + Vertical Refinement + Synthesis is a methodology pattern for coordinating MULTIPLE separate inquiries on a problem whose answer is a position in a multi-axis coordinate space (a configuration, a spec, a framework, a design — anything whose canonical form lists decisions along several roughly-independent dimensions). It runs in three phases:

1. **Horizontal Dive — one inquiry that detects the AXES of the problem.** The horizontal inquiry's job is not to settle the values along each axis but to enumerate which axes exist and what their value-spaces look like. Its output is a coordinate map: the dimensions along which the canonical artifact will eventually be specified.

2. **Vertical Refinement — N follow-up inquiries, one per axis, each declaring `refines:` lineage back to the horizontal parent.** Each vertical inquiry settles its own axis in isolation — values, structure, internal trade-offs, per-axis failure modes — without forcing the other axes' settlements. The verticals can run in parallel in principle; their independence is what makes per-axis specification tractable without cognitive overload.

3. **Synthesis — a final inquiry that rolls up all priors, resolving cross-axis interactions.** Some combinations along the axes have implications that no single-axis specification captured (e.g., axis A's value X interacts with axis B's value Y in a way that requires a new rule, an exception, or a re-derivation). The synthesis surfaces these interactions, names cross-axis architectural patterns, and produces the canonical artifact.

The shape composes EXISTING single-question MVL loops via `refines:` lineage; it doesn't replace MVL — it ORCHESTRATES multiple MVL runs into a coordinated cross-inquiry effort. Each phase is one or more complete MVL loops in its own right. (MVL is homegrown's basic cognitive loop — the Sense-making → Innovation → Critique cycle that solves one question at a time, with surfacing-variant MVLw or exploration-variant MVL+ as extended forms.)

It applies when four conditions hold: (1) multiple approximately-orthogonal dimensions exist (no axis's value is forced by another's; defaults-driving allowed); (2) per-dimension specifiability (each axis can be characterized without first settling every other axis); (3) cross-dimension interactions exist (combinations have implications no single-dimension spec captures); (4) the coordinate space is finite (axes countable; values enumerable per axis — this excludes continuous-parameter problems like ML hyperparameter tuning, where Bayesian optimization or grid search is appropriate instead).

Empirically observed in `comprehenslate`'s 15-inquiry sequence producing the v1.0 translation-configuration canonical spec, where the horizontal inquiry detected ~7 axes (level-system, content-types, action-permissions, harmony-report-apparatus, multi-meaning treatment, dual-tier defaults, asymmetric ordering), the verticals refined each axis, and the synthesis named 9 cross-axis architectural patterns (composite-axis; categorical; asymmetric-ordinal; explicit-zero level; dual-tier default; content-type-by-level table; action-permission table; harmony-report apparatus channel; three-layer multi-meaning treatment). The pattern's mechanism, applicability gate, enablement claims, and failure modes are articulated at HIGH mechanism confidence and MEDIUM generalization confidence (N=1) in the prior finding.

This finding LOCATES Horizontal Dive + Vertical Refinement + Synthesis within the broader Major Thinking-Space Traversal Patterns class as the first admitted member. Horizontal Dive + Vertical Refinement + Synthesis's identity, mechanism, gate, and failure modes are preserved; the reframing adds context without altering its commitments.

### 1. The class — what it IS

**Name: Major Thinking-Space Traversal Patterns (MTTP class).** The user's coinage is preserved.

**Essence:** *The open vocabulary of named, repeatable compositional shapes for multi-MVL-loop work that the future meta-loop draws from when invoking cross-inquiry efforts.*

The class is a **library** (a vocabulary), not itself a pattern. Members of the class are individual patterns. The class's value is providing the meta-loop with named, recognizable affordances — without it, the meta-loop would have to re-derive multi-loop compositions every time from first principles, which would block the autonomy ladder at Level 3+ (per `docs/canon/project_north_star.md`'s autonomy framework, Level 3+ requires the system to autonomously coordinate cross-inquiry efforts based on problem-recognition).

The class is OPEN — new patterns can be added as they emerge or are formalized — in contrast to the closed vocabularies elsewhere in homegrown (the 8 fixed disciplines; the 3 fixed runners; the 7 fixed loop-control moves).

### 2. The 4-level architecture (and the richer 6-level context)

The MTTP class sits at level 3 of homegrown's cognitive operation architecture:

| Level | Unit | Scope | Vocabulary | Example |
|---|---|---|---|---|
| 1 | Discipline | Within one MVL loop | Closed (8 disciplines) | `/sense-making`, `/innovate`, `/td-critique` |
| 2 | MVL Loop | One question | Closed (3 runners: MVL / MVLw / MVL+) | An MVLw run on one question |
| 3 | **Pattern** | **Multi-MVL-loop work** | **OPEN (the MTTP class)** | **Horizontal Dive + Vertical Refinement + Synthesis; Correction-Chain Diagnostic** |
| 4 | Meta-loop | Cross-inquiry orchestration | Closed (7 loop-control moves) + Open (MTTP class) | A navigation session orchestrating multihead MVL+ |

The 4-level architecture above is the **class-centered slice** of a richer 6-level architecture. Below Level 1 (disciplines) is the typed 11-primitive composition per `docs/canon/thinking_space_dynamics.md` (call it Level 0). Above Level 4 (meta-loop) is the autonomy system per `docs/canon/project_north_star.md` — the consciousness-gradient program of which the meta-loop is one component (call it Level 5+). This inquiry focuses on Levels 1–4 because the class lives at Level 3; the levels above and below inform the substrate (primitives) and the motivation (autonomy ladder) but are out of scope for the class definition itself.

The meta-loop at Level 4 uses BOTH vocabularies — the open MTTP class (for the compositional shape of the cross-inquiry effort it's about to invoke) AND the closed 7 loop-control moves (for the decisions it makes at boundaries between loops). The two vocabularies serve different cognitive operations (per the `2026-05-30_09-49` finding's enumerate-vs-decide distinction): patterns are ENUMERATED from an open library and INVOKED to shape an effort; control moves are DECIDED from a fixed repertoire at boundaries within an effort.

### 3. Membership essence — the 5-criterion test

A pattern qualifies as a member of the MTTP class when ALL FIVE criteria hold. Each criterion has a meaning-layer operational definition — a phrasing of "satisfied when [observable condition]" — distinguishing it from a procedural prescription (which would be process-layer and out of scope per the Layer Commitment).

1. **Multi-MVL-loop compositional shape.** Satisfied when the pattern's mechanism references ≥2 MVL loops in its workflow. The pattern composes multiple loops into a coordinated cross-inquiry effort; single-loop methodology (sequential phases within one MVL loop) is at Level 2, not a member of the class.

2. **Named and recognizable.** Satisfied when the pattern has a definite name AND its structural shape can be pattern-matched against problems by the meta-loop (or by a human). Members are named **by SHAPE** (the pattern's structural form) **not by DOMAIN** (the problem area). Horizontal Dive + Vertical Refinement + Synthesis, correction-chain diagnostic, and branch-and-synthesize all follow this convention. Domain-specific applications (e.g., `comprehenslate`'s use of Horizontal Dive + Vertical Refinement + Synthesis to design a translation-configuration framework) are INSTANCES of patterns, not members of the class.

3. **Reusable.** Satisfied when the same shape applies across problem domains. The pattern's identity is the shape, not the domain. A one-domain-only pattern is too narrow to merit class membership.

4. **Evidence-grounded.** Satisfied when at least one empirical instance OR operational specification exists. Pure speculation gets candidate or research-frontier tier status; admitted members require at least N=1 empirical or operational evidence. The two evidence kinds (empirical observation; operational specification) are both valid grounding.

5. **Distinct from the 7 loop-control moves.** Satisfied when the pattern is an open-field compositional shape, not a closed-vocabulary decision. The 7 loop-control moves (TERMINATE / WIDEN / MERGE / RE-RUN-DEEPER / UNBLOCK / DIFFERENT-APPROACH / REVISIT, per the `2026-05-30_09-49` finding) are DECIDED from a fixed repertoire; patterns are INVOKED from the open MTTP library. Different cognitive operations.

The 5 criteria are AND-conjoined (all must hold; not OR; not weighted). Each criterion is binary at admission time. The test is stable across domains.

### 4. 3-tier membership status — with admitted sub-status

Members are placed into one of three tiers based on the evidence supporting them. Within the admitted tier, an additional sub-status tracks per-pattern calibration trajectory parallel to the Horizontal Dive + Vertical Refinement + Synthesis finding's confidence-calibration framework.

| Tier | Admission criterion | Promotion criterion to higher tier |
|---|---|---|
| **Research frontier** | Named in canon or vocabulary; no instance | Operational specification of the pattern emerges (in a homegrown protocol; a finding; etc.) → promote to candidate |
| **Candidate** | Operational specification exists; instance evidence pending | At least one empirical instance verified → promote to admitted |
| **Admitted** | At least one empirical instance verified | Per-pattern sub-status (see below) |

The admitted tier has internal sub-status parallel to Horizontal Dive + Vertical Refinement + Synthesis's calibration trajectory:

| Sub-status | Threshold |
|---|---|
| **admitted-bootstrap** | N=1 empirical instance |
| **admitted-early** | N=2-3 instances with at least one in a domain other than the bootstrap domain |
| **admitted-mature** | N≥5 instances with at least 2 structurally distinct domains represented |

(A "domain" is a problem-type with structurally distinct axes-and-interactions; configuration design, taxonomy design, API design, curriculum design, and decision-framework design each have different cross-axis interaction profiles. The domain definition is inherited from the Horizontal Dive + Vertical Refinement + Synthesis finding's calibration trajectory at section 8.)

The sub-status approach prefers per-pattern qualification within the admitted tier over a separate 4th class-level tier — the "mature" qualification is meaningful per-pattern (signals stronger generalization confidence for that pattern) but doesn't warrant separate class-level tier complexity when the qualification can be expressed as a sub-status.

### 5. Named members + Horizontal Dive + Vertical Refinement + Synthesis's location

The class currently has five named members across the three tiers.

#### Admitted (1 member)

**Horizontal Dive + Vertical Refinement + Synthesis.** Sub-status: admitted-bootstrap (N=1).

- **Shape:** 3-phase fan-out + fan-in — one horizontal inquiry detects axes of a coordinate-space problem, N verticals fan out (one per axis) with `refines:` lineage to the horizontal parent, and one synthesis inquiry rolls up all priors resolving cross-axis interactions.
- **Specialty:** coordinate-space problems satisfying Horizontal Dive + Vertical Refinement + Synthesis's 4-condition applicability gate (multiple approximately-orthogonal dimensions + per-dimension specifiability + cross-dimension interactions + finite coordinate space).
- **Provenance:** prior finding at `devdocs/inquiries/2026-06-08_12-12__horizontal_dive_vertical_refinement_pattern/finding.md`; empirical instance is `comprehenslate`'s 15-inquiry sequence producing the v1.0 translation-configuration canonical spec.

#### Candidates (2 members)

**Correction-Chain Diagnostic.**

- **Shape:** backward-looking 3-loop composition — given a weak prior inquiry + a human correction signal + a later improved inquiry, run a diagnostic MVLw that compares the chain and produces failure hypotheses + maintenance candidates.
- **Specialty:** post-hoc diagnosis of cognitive-system failures across a correction chain.
- **Provenance:** operationally specified in `cognitive_harness/protocols/loop_diagnose.md`. Has been invoked on real correction chains (e.g., the `comprehenslate` polysemy diagnostic) but a formal per-pattern calibration trajectory has not been opened.

**Branch-and-Synthesize (generic).**

- **Shape:** generic parent → branches → synthesis fan-out + fan-in, where the fan-out is not necessarily axis-shaped (could be exploratory branches, perspective branches, alternative-design branches, etc.).
- **Specialty:** any problem amenable to "spawn N sub-inquiries from a parent + roll up via synthesis," where the sub-inquiries don't satisfy Horizontal Dive + Vertical Refinement + Synthesis's specific 4-condition coordinate-space gate.
- **Provenance:** the parent-child mechanism is operationally specified in `cognitive_harness/protocols/branch_inquiry.md`; the synthesis-and-re-test mechanism is in `cognitive_harness/protocols/conclude.md`. Horizontal Dive + Vertical Refinement + Synthesis is one specific instance of this generic shape. Other instances (e.g., exploratory branching during open-ended research) are conceivable but not yet enumerated; the generic pattern itself awaits an instance that exercises the SHAPE outside of Horizontal Dive + Vertical Refinement + Synthesis's specific specialty.

#### Research frontiers (2 members)

**Multihead Parallel Comparison.**

- **Shape:** N parallel MVL+ worker heads running on related sub-questions or different framings of the same question, with one isolated navigation session reading the workers' artifacts and recommending whether to deepen, stop, merge, or redirect each head.
- **Specialty:** future capability for explorations where multiple framings of a problem should be tried in parallel and compared.
- **Provenance:** named as Open Question 4 in `docs/canon/project_north_star.md` ("Parallel MVL loops + cross-comparison — future capability... needs dedicated design near Level 3"). Architecturally elaborated in `docs/canon/towards_cross_run_cognitive_steering_with_isolated_navigation_session.md`. No instance yet.

**Inquiry-Chain Sequential Refinement.**

- **Shape:** temporally-sequential refinement — one inquiry's finding triggers exactly one follow-up inquiry that `refines:` it, producing a linear chain rather than a fan-out.
- **Specialty:** problems where the answer evolves over time through successive refinements, each picking up where the previous left off (rather than fanning into independent sub-problems).
- **Provenance:** the SHAPE is observed across homegrown's inquiry archive (many inquiry chains exist via `refines:` lineage), but it hasn't been formalized as a named pattern with explicit applicability gate, mechanism, or failure modes. Formalization would promote to candidate.

#### Tentative pattern families (provisional)

Members may organize into families as the class grows. Currently with N=5 members, families are tentative; the family taxonomy itself is a candidate, not a commitment.

| Family | Function | Members (provisional) |
|---|---|---|
| **Production** | Forward-building — produce a canonical artifact through multi-loop composition | Horizontal Dive + Vertical Refinement + Synthesis; Multihead Parallel Comparison |
| **Diagnostic** | Backward-looking — diagnose a prior chain or set of inquiries | Correction-Chain Diagnostic |
| **Refinement** | In-place revision — refine a prior commitment through a follow-up | Inquiry-Chain Sequential Refinement |
| **Exploration** | Open-ended branching — explore a space through independent sub-inquiries | Branch-and-Synthesize generic |

Assignments are PROVISIONAL pending N≥5 admitted maturity. The family vocabulary parallels Gang of Four design-pattern families (creational / structural / behavioral) — a known organizing principle from software engineering's pattern-language literature.

#### Horizontal Dive + Vertical Refinement + Synthesis's distinguishing features against other members

Horizontal Dive + Vertical Refinement + Synthesis is currently the only admitted member and serves as a useful reference point. Its distinguishing features against the other named members:

- **vs. Correction-Chain Diagnostic:** Horizontal Dive + Vertical Refinement + Synthesis is forward-looking (builds a canonical spec from scratch); correction-chain is backward-looking (diagnoses a chain of prior work). Different functions; both can coexist within a meta-loop's library.

- **vs. Branch-and-Synthesize (generic):** Horizontal Dive + Vertical Refinement + Synthesis has a specific 4-condition applicability gate restricting it to coordinate-space problems. Branch-and-synthesize (generic) admits broader branching shapes (exploratory; perspective-based; alternative-design). Horizontal Dive + Vertical Refinement + Synthesis is one specific instance of the generic shape.

- **vs. Multihead Parallel Comparison:** Horizontal Dive + Vertical Refinement + Synthesis is sequential — verticals can run in parallel in principle but the synthesis is single-cognizer. Multihead has parallel heads on RELATED questions with explicit cross-head comparison managed by a navigation session.

- **vs. Inquiry-Chain Sequential Refinement:** Horizontal Dive + Vertical Refinement + Synthesis is fan-out + fan-in (one horizontal → N verticals → one synthesis). Sequential refinement is linear (each finding triggers exactly one follow-up). Different topological shapes.
