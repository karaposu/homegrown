Alternative: phenomenological reframe where the operation is unified, with "horizontal," "vertical," "synthesis" being labels for different SURFACES of the same operation. Survives 5-test cycle weakly: loses operational tractability the three-phase shape gives downstream agents.

- Combination: "**Phases + iteration**" — synthesis emits revision triggers that re-fire specific verticals; synthesis re-runs after. Comprehenslate's v1.0 → v1.1 transition via post-synthesis diagnostic fits this pattern.
- Constraint Manipulation (ADD): "Horizontal phase has a hard cap on axis count (e.g., max 12)." Bounds cognitive load. Cost: arbitrary cap loses generality.
- Constraint Manipulation (REMOVE): "`refines:` lineage is removed." Pattern collapses into "N inquiries about related axes + synthesis." Loses auditability. REJECT — confirms `refines:` is load-bearing.
- Absence Recognition (patch): "Horizontal phase trigger for declaring axes complete" — currently implicit. Could be added: explicit "no further axes" statement before deferring values.
- Absence Recognition (redesign): "Phase-0 readiness check before horizontal begins." Currently P6 (applicability gate) is a SEPARATE PIECE; could be RE-LOCATED to a phase-0 within P2's shape. Would make the pattern FOUR-PHASE (Gate → H → V → S). **WORTH FLAGGING for critique.**

- Extrapolation: at extreme scale (50+ axes), H+V+S becomes intractable; synthesis can't hold 50 verticals. **Frontier:** meta-synthesis — synthesize groups of verticals into intermediate canonical specs, then synthesis-of-syntheses. Recursive H+V+S.

### P4 — Why-Useful (MIN coverage + Inversion)

**Principal candidate:** Three solved failure modes — anchor distortion / cognitive overload / pattern invisibility.

**Inversion-candidate (REQUIRED):** "What if H+V+S CREATES failure modes single-inquiry doesn't have?" Yes — coordination cost across inquiries; lineage maintenance overhead; synthesis being a bottleneck (only one cognizer can synthesize at a time even if verticals are parallel); "wrong axes" hiding behind correctly-refined verticals (the verticals look good but the coordinate system is wrong). **Survives** — should be added as trade-off discussion.

- Combination: combine the three arguments — they're not independent. Anchor distortion + cognitive overload together produce "settle one axis right and the rest wrong" (the failure single-inquiry typically produces). The combined argument is stronger than individual.
- Domain Transfer: from systems theory, "decomposition for tractability is the master pattern of complex-system management" (sciences chemistry→biology; engineering modular design; administration departments). H+V+S is one instance of this master pattern.

### P6 — Applicability Gate (FULL coverage)

**Principal candidate:** Three-condition test (multiple orthogonal dimensions + per-dimension specifiability + cross-dimension interactions).

**Inversion-candidate (REQUIRED):** "What if NO conditions are needed — H+V+S applies universally?" REJECT — for simple problems, H+V+S is overkill. *Deeper inversion:* "What if the gate is wrong direction — H+V+S applies by default and the user must declare 'NOT an H+V+S problem'?" Changes the default. Pros: prevents under-application. Cons: increases overhead for simple problems. Trade-off.

- Combination: "Gate + Layer Commitment trigger." If a problem targets a discipline/protocol/framework artifact AND meets the 3-condition test, H+V+S applies. Combines two existing homegrown triggers.
- Constraint Manipulation (ADD): "Fourth condition: coordinate space is FINITE (axes countable; values enumerable per axis)." Distinguishes from problems with continuous variation. **WORTH FLAGGING.**
- Constraint Manipulation (REMOVE): "Relax 'orthogonal' to 'approximately orthogonal' (small cross-axis interaction)." Comprehenslate's A4 drives defaults for others — moderate interaction, not strict orthogonality. Existing test is already approximately-orthogonal in practice; explicit relaxation aligns spec with practice. **WORTH FLAGGING.**
- Absence Recognition (patch): "Prior-art check." Comprehenslate could have used CEFR for reader axes (already exists); the gate should ask "is this problem already solved by an existing framework?" Sub-condition.
- Absence Recognition (redesign): Gate becomes a multi-question diagnostic that classifies problem TYPE and recommends pattern (H+V+S / single-inquiry MVL / iterative MVL+ / etc.). Gate as router, not binary test. **WORTH FLAGGING for critique.**
- Domain Transfer (cognitive load theory): "Intrinsic vs extraneous load." H+V+S reduces extraneous load at cost of total work. Gate could be condition-bound: "applies when intrinsic load > N." N is calibration-dependent.
- Lens Shifting: under "AI cognitive economics" lens (cheap LLM calls), H+V+S has low cost; under "human-driven" lens, high cost. Gate condition shifts based on cognizer.
- Extrapolation: if AI inquiry cost approaches zero, gate widens. Currently calibrated for mixed AI/human cost.

- Absence Recognition: "Prevention category." SV6 lists failure modes (detection) and recoverability (recovery). Missing: prevention. Prevention vs detection vs recovery is three categories. Worth adding. **WORTH FLAGGING.**
