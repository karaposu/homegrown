- **The option-space is four axes:** MOMENT (boundary / event / schedule; threshold rides any; human-fired ≈ pull) × CHECKER (script / session / hybrid — scripts watch numbers, sessions read meaning, hybrid rations the expensive one) × CHECK-CONTENT (countable: frontier growth, view staleness, routes aging, chain-quiet · semantic: collisions, contradictions, relitigation-in-progress) × DELIVERY (conditional header line / dated alert-note / session-start banner / device notification / blocking gate — named the fatigue cliff).

## Finding

### 1. How push is possible here (the mechanism)

The contradiction is only apparent. "Something watches" does not require something RUNNING. A watcher decomposes into a check, a moment, and an interrupt — and all three exist in a sessions-and-files world. The CHECK computes from artifacts: frontier counts, staleness deltas, and aging routes are greps; collisions and contradictions need a reading session. The MOMENT is ridden, not resided-in: every warm-up is a moment; a git hook makes any landing a moment; a cron entry makes any night a moment. The INTERRUPT outlives its maker by becoming an artifact — a dated note whose reading is a mandatory warm-up step — or by landing at one of the three genuinely interruptive grains: a session's first tokens (banner), a tool-boundary (wired hooks), or your device (a real notification).

What makes this PUSH rather than elaborate pull is the initiation-locus: in every pull family, the reader's question selects the content; here the content selected itself — a threshold crossed, a collision found — before any reader existed. The strongest counter ("this is polling with extra steps") wins two concessions worth keeping: alert-notes-only designs are honestly *push-initiated, pull-delivered*; and the ceiling is exact — no external relevance can interrupt a working session mid-thought, ever, in this architecture.

### 2. The variations (the four axes)

| Axis | Options |
|---|---|
| **MOMENT** | boundary-fired (every warm-up) · event-fired (git/file hooks) · schedule-fired (cron, guard-gated) · [threshold = sub-mode riding any] · [human-fired = boundary case ≈ pull] |
| **CHECKER** | script (greps; cheap; countables) · session (reads meaning; expensive) · hybrid (scripts gate the session) |
| **CHECK-CONTENT** | countable: frontier growth · view staleness · open-routes aging · chain-quiet — semantic: new-vs-old collisions · contradiction candidates · relitigation-in-progress |
| **DELIVERY** | conditional header line · dated alert-note (`devdocs/alerts/`, window-acknowledged) · SessionStart banner · device notification (graves only) · blocking gate (the fatigue cliff) |

### 3. The archetypes (coherent bundles — marked, never selected; they stack)

1. **The Warm-up Sentinel** — boundary · script · header lines. A gauge panel whose CONDITIONAL lines are the watcher (the gauge→watcher gradient). Catches countable drift. Costs ~nothing; zero wiring; half-shipped already (`frontier: N`).
2. **The Landing Check** — event · script · one line. Catches a new arrival breaking countable rules the moment it lands. Costs one wired hook.
3. **The Nightly Sweeper** — guard-gated cron · hybrid · alert-notes (+banner). Step 1 always: *did anything land since the last sweep?* — exits in seconds when quiet; the session reads only on change, and only the landed material against the constraints it touches. The purest "uninvited"; the semantic checks' home. Ends at note-writing, by its own terminal line.
4. **The Deep Auditor** — sparse cron · session · alert-notes + device-for-graves. Hunts slow rot (mandate-coverage decay; cross-month contradictions). Rationed by design; the only archetype allowed to reach your pocket.

**Anti-bundles:** session-grade on every event (expensive noise) · blocking gates with low-precision checks (the fatigue cliff) · device pushes for non-graves (trust-spending). **Stacking:** the four ride different moments and share the alerts home — all four can coexist; which (if any) runs first is your pick.

### 4. The walls (every variation bound)

1. **The valve:** watchers RECOMMEND — they write notes; they never open inquiries, run ceremonies, generate views, or edit protocols. Session-grade watchers carry the terminal line verbatim: *the sweep session ends at note-writing; its last act is the note.*
2. **Pre-registration:** watcher outputs are view-class — dated, pointed, quoted-basis, subordinate, regenerated-never-edited — homed at `devdocs/alerts/` (outside the views tree; critique's placement catch). **The wall-sentence: watchers report what the territory shows; they never record what anyone chose about it.** A collision-note passes; a pursue/dismiss record is the write-half — the user's open decision, untouched by this design.
3. **Fatigue:** precision before recall; thresholds are protocol constants (set at build, changed by you, never self-adjusted); the volume cap (~3 notes/day, overflow → one summary-note; ≤5 header lines; device once-per-grave); acknowledgment by window (K days), not mechanics.

### 5. The two worked paths (illustration, not selection)

**Cheapest — the Sentinel (zero wiring):** the digest header, which the build already carries, gains `stalest-view: <concept> (<days>d behind)` and `aging-routes: <n> open >30d`; each line has a conditional form that fires past its spec-constant threshold. Nothing else — no files, no state, everything derived per run.

**Purest — the Sweeper (one cron session):** (1) the guard: anything landed since the last sweep-mark? quiet → exit in seconds; (2) on change: run the countable greps, then read ONLY the landed findings' summaries against the old constraints they touch; (3) each real find → `devdocs/alerts/<date>.md` (pointer + one line + quoted basis; no selections recorded); (4) the next warm-up reads alerts newer than K days; a banner can surface the newest line if hooks are wired. Ends at the note.
