## State Summary

- **Territory echo:** routelister spec (attributive-field design + identity boundaries) + 12 real crowboy route-maps.
- **Purpose echo:** is an essentiality/immediacy tag a distinct attributive axis or a re-slice of Priority; is it identity-clean; what's the best categorization — without bloat.
- **Coverage map:**
  - *Priority's current meaning* — **confirmed.** Priority = perceived salience/importance toward the goal (§1.5/§2.2). It is the existing carrier of "how much this matters."
  - *The identity boundaries* — **confirmed.** Two hard lines: (a) Selection-creep — a tag may describe a route's salience/coreness but must not *decide* act/defer/drop (the "immediate" half of the proposal is the risk — "do it now" is a disposition); (b) no dependency graph — "essential" must be a route↔goal attribute, not a route↔route "A needs B."
  - *The empirical pain* — **confirmed + measured.** Priority over-compresses: 5–6 HIGHs per busy map, 8–11 mid/high; the user can't tell which HIGHs are goal-core. Essentiality judgments are already being made but buried in WHY prose.
  - *The essential-vs-immediate split* — **confirmed real.** R10 (essential-but-later) vs R3 (essential-now) vs R13 (peripheral) are three distinct, measured cells. "essential immediate" fuses two orthogonal axes.
  - *The bloat tension* — **confirmed.** The lean-index redesign just dropped 2 columns; any realization must not re-inflate (candidate homes: the existing `tags:` line; a Header count; a record sub-field — NOT necessarily a new index column).
- **Confirmed-absent:** no existing routelister field cleanly captures "is this route on the critical path to the goal?" — it is *only* expressed (inconsistently) in WHY prose. There is no current essentiality/coreness attribute distinct from Priority.
- **Concept-names surfaced:** Priority-as-salience · disposition-vs-attribute (Selection-creep) · route↔goal-vs-route↔route (dependency-graph boundary) · Priority-compression · essentiality-latent-in-WHY · essential≠immediate · Confidence-as-orthogonal-precedent · vitality-rubric-as-meta-rating-template · lean-index-bloat-constraint · goal-relative-essentiality · the-tags-line-home · engagement-type-weak-proxy.
- **Frontier flags (for sensemaking):**
  1. **Is essentiality distinct from Priority, or a re-slice of it?** The data says Priority *fuses* essentiality + immediacy + raw-salience into one HIGH/MED/LOW scalar — so essentiality is a *sub-component Priority currently compresses*, not a wholly new property. Sensemaking must decide: decompose Priority, add ONE orthogonal axis, or add TWO.
  2. **Does "immediate" cross into Selection-creep?** "essential" (a property: on the critical path) looks attributive-clean; "immediate" (do it now) flirts with disposition. Sensemaking must find an attributive framing of immediacy (e.g., "on the critical path *now* vs *later*" = a fact about the goal's phase, not a command) or drop it.
  3. **Where does it live without bloat?** Index column vs `tags:` line vs Header count vs record sub-field — adjudicate against the just-finished lean-index.
  4. **Goal-relativity** — essentiality flips with the live lens (R13) and phase (R10). The tag must be goal-relative-by-construction, not an absolute "this route is important."
