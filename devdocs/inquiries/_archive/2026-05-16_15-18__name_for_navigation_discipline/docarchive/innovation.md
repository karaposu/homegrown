## Direction (Intuition Signals)

- **Context.** Local project vocabulary anchors: "direction" (route-card field), "concept" (docs/nav.md framing), "next" (user-language), "Navigator" (autonomy-ladder role-noun), 16-type taxonomy. Sibling discipline names mix verb-form (`/innovate`, `/explore`, `/decompose`, `/comprehend`, `/reflect`) and noun-form (`/sense-making`, `/td-critique`, `/meta-loop`).
- **Valuation.** The user values fit-to-essence + low switching cost (per Sensemaking).
- **Motivation.** The user's question signals doubt about the current name; the verdict should be a real recommendation, not status-quo by default.

## Phase 2 — Generate (apply all 7 mechanisms)

### 1. Lens Shifting (Framer)

Current frame: discipline name evokes what discipline DOES.

**LS-Generic.** Reframe under "what does the OUTPUT look like?" The discipline produces a *navigation map*. Name candidates: `/direction-map`, `/route-map`, `/possibility-map`.

**LS-Focused.** Reframe under "the autonomy-ladder role." The Navigator role plays this discipline. Candidate: `/navigator` (agent noun). Breaks action-noun convention; introduces internal inconsistency.

**LS-Contrarian.** Reframe under "the user types this as a slash command, not a discipline name." Terseness and typing-ease matter. Candidate: `/nav`. Conflicts with project's existing verbose-naming convention.

### 2. Combination (Generator)

Concepts in local proximity (scope-fidelity: narrow project scope):
- "next" (user-language)
- "directions" (project-vocab)
- "concepts" (docs/nav.md framing)
- "moves" (sibling naming + chess "candidate moves")
- "map" (output artifact)
- "routes" (route-card unit)

**CB-Generic.** *next + directions* = `/next-directions`. Combines user-language with project-vocab. Hyphenated; sibling-consistent.

**CB-Focused.** *directions + map* = `/direction-map`. Project-vocab + output-artifact framing.

**CB-Contrarian.** *concept + map* = `/concept-map`. Uses docs/nav.md's design-history framing directly ("everything in navigation is concept").

### 3. Inversion (Framer)

Current belief: "name should describe what the discipline DOES" (verb-meaning).

**IV-Level-1.** Inverted — name should describe what's PRODUCED (noun-output). Candidates: `/direction-map`, `/route-cards`, `/options`.

**IV-Level-2 (system-level).** Inverted — the discipline isn't about names; it's about MOVEMENT-MAKING-EXPLICIT. Candidate: `/explicate` or `/surface-moves`.

**IV-Contrarian.** Don't name by operation; name by POSITION-IN-LOOP. Candidate: `/post-conclude` or `/after-finding`. Breaks project's discipline-naming convention.

### 4. Constraint Manipulation (Framer)

Current constraints: single-word or hyphenated; fit-to-essence; small switching cost.

**CM-Generic.** Remove "short-name" constraint. Maximally precise: `/enumerate-typed-next-directions`. Too long; rejected by readability.

**CM-Focused.** Add constraint: "name must use project-internal vocabulary." Survives: `/directions`, `/concept-map`, `/route-cards`. Kills generic English options.

**CM-Contrarian.** Add constraint: "name must introduce NO new vocabulary." Survives: `/directions` (route-card field), `/navigation` (status quo), `/navigator` (autonomy ladder). Kills `/next-moves` ("moves" is new), `/concept-map` ("concept-map" as compound is new).

### 5. Absence Recognition (Generator)

**AR-Gap (Generic).** Missing a name that captures the discipline's FILTERING nature (gates check). Candidate: `/reachable-directions` or `/gated-directions`.

**AR-Gap (Focused).** Project uses "navigate" as a verb in cross-references but `/navigation` (noun) as the discipline name. The verb form is **missing**. Candidate: `/navigate` — single-letter rename from current. Aligns with verb-form sibling cluster (`/innovate`, `/explore`, `/decompose`, `/comprehend`, `/reflect`) AND pairs cleanly with the autonomy-ladder role-noun "Navigator" (verb → agent-noun: navigate → Navigator, same as explore → Explorer, innovate → Innovator).

**AR-Redesign.** A genuinely new name not constrained by current vocabulary: `/orient`. Semantically: "to orient" = establish position AND direction; the navigation map does exactly this (establishes WHERE the inquiry stands + WHAT next-directions exist). Single-word; verb form; sibling-consistent; semantically distinct from `/navigation`.

### 6. Domain Transfer (Generator)

**DT-REST (Software).** RESTful naming convention: name resources as NOUNS, not verbs. Apply: `/directions`, `/routes`, `/moves`.

**DT-Linnaean (Science).** Disciplines named after the object they study (biology = bios). Apply: discipline operates on directions → `/directions`.

**DT-Wayfinding (Cognitive Psychology).** "Wayfinding" in cognitive psychology = spatial orientation in unfamiliar territory. Reviving `/wayfinding` has the deprecation-confusion problem; the cognitive-science concept itself maps cleanly. Convergent with N5 `/orient` (which captures the wayfinding concept without name collision).

**DT-Chess.** Chess names this operation "generating candidate moves." Candidate: `/candidate-moves`. But "candidate" is already used in the project (innovation outputs, critique evaluation targets) — collision.

### 7. Extrapolation (Generator)

**EX-1-year.** If the discipline's role grows over time (absorbs Selector or Evaluator operations), the name needs flexibility. `/navigation` is flexible; `/directions` is purely enumeration-bound. `/orient` is flexible.

**EX-5-year.** At project Level 3+, the autonomy ladder has Selector as a separate role. If Selector ever folds into navigation, `/navigation` fits better than `/directions`. Slightly favors status-quo or `/navigate` over narrow names.

**EX-10-year.** At Level 5+, runner-level architecture dominates; individual discipline names matter less. Naming question becomes lower-stakes over time.

## Hand-off to Critique

Critique should subject the candidates to adversarial testing on the 7-dimensional naming landscape. The decisive comparisons:

1. **W2 (`/directions`) vs N4 (`/navigate`)** — these are the two strongest renames. W2 wins on precision-to-essence; N4 wins on switching cost + role-noun pairing. Which wins overall?

4. **W3 (`/next-moves`) vs W2/N4** — does the user-language win in W3 outweigh the new-vocabulary cost of introducing "moves"?
