## Phase 3 — Ambiguity Collapse

### Ambiguity 1 — MC1 wording: does the 3-axis-category list need exhaustiveness?

**Counter-interpretation:** "Listing only 3 categories implies exhaustiveness. Future runners may interpret the spec as: 'enumerate exactly these 3 axes and no others.' Better to leave the list permissive or extensible."

**Why the counter partially fails:** the draft wording explicitly says "at minimum" + "The runner may add additional axes as substance warrants" — this signals non-exhaustiveness. Permissive framing IS in the draft.

**Resolution:** the draft's "at minimum" + "may add additional axes" is sufficient. Critique can stress-test whether the permissive framing is clear enough.

**Confidence:** HIGH.

### Ambiguity 2 — MC1 trigger phrase: bounded enough?

**Counter-interpretation:** "Per-option comparison structure" is fuzzy. A runner might NOT recognize their option table as a "structure" if it's informal (2 options; brief text).

**Why the counter has merit:** the draft's "pros/cons table; multi-attribute scoring grid; ranked list with stated criteria" specifies 3 example shapes. A runner with a 2-option informal pros/cons paragraph might think the rule doesn't apply.

**Resolution:** add explicit threshold — "3+ options" OR "with stated criteria" — to narrow to substantial comparisons. Actually the existing wording "ranked list with stated criteria" already implies some formality. The minimum threshold is: any structure where the runner is COMPARING options on criteria. Informal 2-option discussions don't qualify.

Refined wording: "When a possibility-mode scan produces a per-option comparison structure (pros/cons table; multi-attribute scoring grid; ranked list with stated criteria), enumerate the comparison axes BEFORE populating per-option cells" — the "comparison structure" + "stated criteria" is the threshold. Informal text discussions don't fall under "structure."

**Confidence:** MEDIUM-HIGH. Critique can stress-test this further.

### Ambiguity 3 — MC2 wording form: list extension vs separate sentence

**Counter-interpretation:** "Extending the existing list inline is cleaner and shorter than a separate sentence."

**Why the counter partially fails:** the existing list is past-tense ("across recent inquiries"). Adding a forward-looking exemplar mixes tenses.

**Resolution:** SEPARATE SENTENCE wins per the past-tense framing concern. The draft above commits this.

**Confidence:** HIGH.

### Ambiguity 4 — MC3 sub-aspect phrasing

**Resolution:** the draft phrasing follows the existing pattern. Single multi-clause question with concrete invariants named. Sufficient.

**Confidence:** HIGH.
