**The Boundary-discovery sub-phase** is a conditional pre-phase that fires only when the territory is implicit (the inquiry does not pre-specify the territory's bounds). When fired, it probes outward to surface the territory's edges; its output is a territory-specification that becomes the input to the main Reception phase. When the territory is explicit (concrete pre-specified — a codebase, a literature topic, a corpus; or abstract pre-specified — a conceptual space with explicit description), the sub-phase is skipped.

**The 6 components within the Traversal phase** are not sub-phases (they don't have strict temporal ordering relative to each other); they are operations that fire as needed within each iteration of the Traversal cycle:

| Component | Role |
|---|---|
| **Scope-determination** | Decide which sub-region of the territory the current cycle operates on |
| **Item-enumeration / generation** | List existing items (artifact mode) OR generate candidate items (possibility mode) within the current sub-region |
| **Relevance-attribution** | Apply the relevance-attribution mechanism (P2) to each enumerated/generated item; produce per-item relevance tag |
| **Coverage-tracking** | Maintain a record of which sub-regions have been operated on at which resolution |
| **Absence-detection** | When a sub-region is operated on and contains no relevant items, mark the sub-region as confirmed-absent (a productive output, not a gap) |
| **Output-shaping** | Accumulate the per-item tags + region annotations into the in-progress inventory; prepare for Assembly |

**Re-invocation semantics: parameterized variation of the same operation.**

Re-invocation is NOT a distinct operation. It is the same 3-phase + sub-phase shape with additional input parameters:

| Optional input parameter | Effect when present |
|---|---|
| **prior-inventory** | Reception incorporates the prior inventory; Traversal can skip already-surfaced items (using prior inventory as exclusion-filter); Assembly merges the new tags with the prior inventory rather than producing a fresh inventory |
| **refined-sub-purpose** | Reception uses the refined-sub-purpose as the relevance-bias-source for THIS invocation (the inquiry's overall purpose remains; the refined purpose narrows the bias scope) |

The operation's identity is preserved across invocations; only inputs and intermediate behavior parameterize.

**Re-invocation triggers** (the conditions under which a runner or downstream signal warrants re-invoking surfacing):

- Downstream discipline identifies a sub-region not yet surfaced
- Inquiry purpose narrows (a sub-question emerges that needs its own surfacing)
- Inquiry purpose widens (the original scope was too narrow)
- Coverage gaps surfaced by the discipline itself (the discipline self-signals re-invocation; see P6 failure-mode framework + P7 calibration's re-invocation-rate signal)

## PHASE D: P6 — FAILURE-MODE FRAMEWORK

### Seed (P6)

**Question:** What is the discipline's failure-mode framework, including the asymmetric-failure principle's operational form?

**Inputs from priors:** D8 (asymmetric-failure operational form), D9 (LAYER 1 / LAYER 2 framework).

### Generate (P6)

**Mechanism — Lens Shifting:**

Lens 1 (Standard failure-mode framing): "Failure modes are things that go wrong; the discipline tries to avoid them." Under this lens, all failures are equivalent in kind.

Lens 2 (Information-flow framing): "Failure modes are observed via downstream consequences; the discipline's failures cascade into downstream operations." Under this lens, asymmetry emerges: false-negatives are unrecoverable; false-positives are recoverable. This is the user's clause-(e) framing.

Lens 3 (Identity-vs-operation framing): "Failure modes split into operational failures (the discipline didn't do its operation well) and identity failures (the discipline did something it shouldn't have done)." Under this lens, failures split into LAYER 1 (operational) and LAYER 2 (identity).

The 3 lenses together produce the LAYER 1 / LAYER 2 framework with the asymmetric-failure principle embedded.

**Mechanism — Inversion:**

Inversion: "What if surfaced-irrelevance were structurally worse than missed-relevance?" This would mean: the discipline should err toward filtering, not inclusion.

Test of the inversion: under this inverted framing, downstream disciplines would receive a tightly-filtered inventory. But if any RELEVANT item was filtered, downstream cannot recover it. The user's clause-(e) framing directly contradicts this inversion. The inversion FAILS on user-clause grounds + information-flow asymmetry grounds.

The correct framing: missed-relevance > surfaced-irrelevance in cost. Lean toward inclusion.

### Test (P6)

**Final P6 content:**

**The asymmetric-failure principle:**

Missing a relevant item is structurally worse than surfacing an irrelevant item. Reason:

- **False-positive (surfaced irrelevant):** downstream disciplines see a tagged item that doesn't actually bear on the inquiry. Cost: downstream filters or critiques the item out. Recovery is cheap (filter, ignore, defer). The item remains in the inventory; downstream allocates effort to recognizing it's irrelevant; effort is bounded.

- **False-negative (missed relevant):** a relevant item is never tagged, never entered into the inventory. Downstream disciplines never see the item. Cost: downstream operates on an INCOMPLETE inventory; produces conclusions that depend on items that were never considered. Recovery is only via re-surfacing (re-running the discipline with revised purpose); but downstream has no way to KNOW the missing item exists because surfacing didn't surface it. This is the **information-loss-in-the-dark failure mode** — the system doesn't know what it doesn't know.

**The principle's operational form:** the discipline leans toward INCLUSION under uncertainty. The stop-rule is **territory-bounded traversal + uncertainty-includes filtering**:
