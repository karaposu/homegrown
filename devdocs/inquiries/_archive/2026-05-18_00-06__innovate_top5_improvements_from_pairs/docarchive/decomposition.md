## Step 6 — Order by Dependency

**Linear chain:**

```
[Sensemaking: 5 commitments]
       │ (input contracts via I3)
       ▼
   P1 (Selection) ──────► P2 (Specification) ──────► P3 (Assembly)
                              ▲
                              │
                              I4
                              │
   [Exploration: per-pair mapping]
```

**Dependency order:**

1. **P1 — Selection** — must run first. Without P1's chosen set + consolidation outcomes, P2 has no candidates to specify.
2. **P2 — Specification** — runs after P1. Depends on P1's outputs (the 5 chosen) and Exploration's pair-mapping (for pair-evidence pointers).
3. **P3 — Assembly** — runs last. Depends on P2's fully-specified records.

**No parallelism possible** within this decomposition — each piece consumes the prior's output entirely. (The work could be conceptually parallelized if a hypothetical P1-P2 pair were generated per-candidate, but in this sequential conversation it's strictly linear.)

**No circular dependencies.**
