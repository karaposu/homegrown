# Branch: Next Discipline Candidate

## Question
What cognitive discipline should be added to the cannon set next — i.e., which named or yet-unnamed cognitive operation is the highest-value next addition, given the current cannon (`explore`, `sense-making`, `decompose`, `innovate`, `td-critique` / soon `adjudicate`) and the project's accumulated history of named-but-unbuilt disciplines?

## Goal
A recommended next discipline (or a ranked short list of 2-3 finalists) with reasoning the user can adjudicate. The recommendation should:
- Identify what cognitive operation the discipline performs (the meaning layer).
- Explain why this is the next priority over alternatives.
- Note dependencies (does the discipline require something else to be built first?).
- Map to the project's existing milestones or named-but-unbuilt entries if applicable.

Operational test: the user can read the recommendation and either commit to designing the new discipline (followed by structural + process inquiries to define its spec and procedure) or override with their own pick.

## Scope Check
Question covers goal: YES.

Specific-vs-pattern: the user asked "what discipline" (singular). Default scope is a single recommendation with 1–2 alternatives. The broader pattern ("how should the discipline taxonomy evolve over time?") is adjacent; surface only if it becomes load-bearing for adjudicating the recommended next pick.

The inquiry's reasoning will be informed by these inputs (read but not synthesized as commitments):
- The current cannon set (`explore`, `sense-making`, `decompose`, `innovate`, `td-critique` / soon `adjudicate`).
- The recently-archived experimental skills now at `cognitive_harness/_archive/` per the context-blur inquiry's outcome (decision not yet executed; archived candidates: `navigation`, `meta-loop`, `comprehend`, `reflect`).
- Named-but-unbuilt entries from prior findings (e.g., Predictive RC / `intuit`, Retrospective RC / reflection; the safety-substrate / self-maintenance arc; quality-awareness layers).
- The cognitive loop's current coverage (`E → S → D → I → C`) and what cognitive operations it does NOT yet cover.

These are research inputs, not formally-synthesized prior outputs — no Synthesis Trigger applies.

## Layer Commitment

**Primary layer: meaning.**

The question targets a meta-design choice about the discipline taxonomy — WHAT cognitive operation the next discipline should perform, what concept it adds. Meaning adjudicates name, definition, essence. The right candidate cannot be picked without first clarifying which gap in the current cannon the new discipline fills.

Out-of-scope for this run:
- **Structural** — the new discipline's spec sections, references-file organization, schema. Comes after meaning is settled. A follow-up inquiry handles structural design once the user commits to a candidate.
- **Process** — the new discipline's procedural steps, phases, gates. Downstream of meaning + structural.

Sequential plan: this inquiry commits the meaning (what operation, what gap it fills, what role it plays). If the user commits to a candidate, the next inquiry is structural (spec design). Then process (procedural steps + integration with `/MVL+`).

The primary layer is unambiguously **meaning** because the user asked "what is next" — an identity-of-operation question. Structural and process are downstream once identity is fixed.
