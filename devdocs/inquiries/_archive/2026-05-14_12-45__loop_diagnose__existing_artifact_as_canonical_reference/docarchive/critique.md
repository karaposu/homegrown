## Phase 2 — Adversarial Evaluation

### Multi-axis prosecution depth check

**(a) L1 operational-clarity probe.**

Prosecution: *"The pre-step prompts for 5 canon-status categories (canon / non-canon / under-test / historical / unknown). The categories aren't fully orthogonal. Two readers facing the same artifact could plausibly answer differently — a reader who treats 'exists in project' as canonical would say `canon`; another reader treating 'looks like an old attempt' would say `non-canon`. The 'unknown' answer is permissive enough to defeat the check if used as default."*

Defense: *"The categories have operational distinctions: `canon` = 'represents current intent for this question'; `non-canon` = 'exists but is legacy/abandoned'; `under-test` = 'the inquiry's test target'; `historical` = 'preserved record but not current intent'; `unknown` = 'status not determined; proceed with caveat.' The 'unknown' answer is acceptable because making the implicit explicit is the value, not forcing a binary judgment."*

Collision: defense holds in principle but prosecution surfaces a real operational-clarity gap. The categories are operationally distinct in intent but the prompt as currently written doesn't include disambiguation examples. **REFINE-worthy.**

**R1:** Add brief illustrative examples per category to L1's prompt design. E.g., for `non-canon`: "an existing /navigation discipline spec that was an earlier attempt but doesn't represent the user's current intent for `navigation`." This reduces two-reader inconsistency.

---

**(b) Self-reference genuineness probe.**

Prosecution: *"The self-reference acknowledgment notes /explore spec was sourced from installed runtime version, not canonical at homegrown/explore/. The acknowledgment is HONEST about the limitation but the inquiry could have ACTUALLY checked whether homegrown/explore/explore.md exists and matches. A genuine application of the proposed L1 lesson would have done the check; the acknowledgment is performative-honesty without performative-action."*

Defense: *"The acknowledgment surfaces the limitation transparently; that's value. A future reader can verify if needed."*

Collision: prosecution wins. The acknowledgment is genuinely honest but doesn't fully apply the lesson. A self-reference that applies the lesson would either (a) actually check the canonical version's existence and content, OR (b) commit to doing so as a follow-up action. **REFINE-worthy.**

**R2:** Strengthen self-reference acknowledgment with one of two options: (option A) actually check homegrown/explore/references/explore.md (if it exists) for divergence on load-bearing content; (option B) commit to a follow-up action — "verify homegrown vs installed /explore divergence before treating this diagnostic's structural reductions as fully grounded." The current acknowledgment naming the limitation is good; this strengthens it from "noted limitation" to "applied lesson."

Collision: defense holds cleanly. The calibration note addresses the prematurity concern; the family name is sufficiently specific (meta-conditions on verification, not just "meta-conditions"). Three concrete cases + calibration > pattern-axiom. **PASS.** No REFINE needed.

**(d) H1-primary vs cascade-primary scrutiny.**

Prosecution: *"H1 (framing-time) is named primary; H2 (cascade) is supporting. But could it be the reverse? The cascade made the existing /navigation spec EXIST in the project; without the spec existing, the assistant wouldn't have referred to /navigation at all in conversation. So cascade is causal; framing-time is downstream."*

Defense: *"The cascade made the spec EXIST in the project, but the framing-time failure was the COMMITMENT to use the existing spec as authoritative WITHOUT checking status. The cascade is CONTEXTUAL (it's what made the spec available); the framing-time failure is the ACTIONABLE intervention point (where the L1 pre-step would fire). Even WITH the cascade in place, a framing-time canon-status check would have caught the failure. The maintenance candidate addresses the framing failure, not the cascade."*

Collision: defense holds. The distinction is contextual vs actionable: cascade is the contextual condition that made the spec available; framing-time is where the actionable failure occurred. H1-as-primary is structurally correct because that's where the intervention lives. **PASS.** No REFINE needed.

Prosecution: *"This is the 4th MVL+ inquiry in 24 hours related to the same topic chain (verification-1 spec; verification-2 concept; LOOP_DIAGNOSE on the chain). High cognitive cost. Could L1 have been written directly, skipping the full pipeline?"*

The previous corrected inquiry (2026-05-14_00-26) already named "honest cost-naming for three verifications" as a meta-lesson; this LOOP_DIAGNOSE inquiry extends that — four MVL+ in succession with cumulative learning. **REFINE-worthy for the finding's framing.**
