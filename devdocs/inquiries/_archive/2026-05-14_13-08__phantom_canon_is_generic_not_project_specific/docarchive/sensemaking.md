### Ambiguity 2: Recursive Demonstration treatment

**Counter:** "Fold into existing self-reference acknowledgment — they're both about applying the lesson to itself."

**Why counter partially fails:** The previous self-reference was about /explore canonical-vs-installed (artifact-level). The recursive demonstration is about the L1 SPEC ITSELF (spec-level). These are different layers; conflating them obscures the meta-meta-level insight.

**Resolution:** Separate top-level piece named explicitly (e.g., "Recursive Demonstration: The Previous Finding's L1 Exhibited Phantom Canon"). **HIGH** confidence.

### Ambiguity 3: Meta-check standing rule vs one-time

**Counter:** "One-time correction is sufficient; the user pointed out the issue; we fixed it."

**Why counter fails:** Future revisions to L1 (in this project or others) could over-specify again without a standing check. The meta-check is preventative. Without it, the lesson-introduces-its-own-trap pattern can recur.

**Resolution:** Standing rule embedded in the corrected L1 spec ("when defining or revising L1's trigger criteria, also check: are these criteria assuming a particular project's structure/conventions, or do they apply across projects?"). **HIGH** confidence.

### Ambiguity 4: Project-boundary element

**Counter:** "Generic formulation is enough; project-boundary declaration adds bureaucracy."

**Why counter partially fails:** Generic formulation IS enough for most cases. But explicit project-boundary declaration HELPS in cases where the project has non-standard structure (e.g., monorepos with multiple sub-projects; multi-vendor codebases). Soft inclusion (optional) addresses this without bureaucracy.

**Resolution:** Optional soft element in the corrected L1's pre-step prompt: "If your project has non-standard structure, optionally declare the project's structural conventions to help interpret artifact references." **MEDIUM** confidence.

### Ambiguity 5 (LOAD-BEARING CONCEPT TEST): "generic trigger"

**Counter:** "Generic is too vague; the trigger should be more concrete."

**Why counter partially fails:** The B1 formulation ("ANY artifact reference where canon-status could be ambiguous") combined with B2 ambiguity threshold ("if you can't easily say...") provides operational specificity. The B3 diversified examples ground the abstraction. Generic + threshold + examples = operationally concrete without project-binding.

**Resolution:** "Generic trigger" stays as the concept; B1+B2+B3 together provide operational specificity.
