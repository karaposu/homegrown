### 2. The hybrid α+γ operational identity

This finding commits the section's operational identity as **hybrid α+γ**, where:

- **α (substrate-cumulative-library; CORE):** single home for cross-inquiry named LLM-cognitive biases. Provides cumulative discovery — a future runner browses the library without needing Synthesis Trigger inheritance from specific priors.

- **γ (optional discipline cross-references; SECONDARY):** existing discipline failure-modes lists CAN reference library entries when relevant; library entries can list applicable disciplines. Cross-references are bidirectional in concept (library → discipline; discipline → library) and OPTIONAL (the library functions without them; cross-references add operational hooks when relevant).

**Three operational-identity options were tested at Sensemaking + Innovation:**

- **Pure option α** (substrate-cumulative-library only; no discipline cross-references): REJECTED — without operational hooks, the library becomes read-only documentation; passive availability alone limits operational reach.

- **Option β** (mechanism-active-enforcement; each named bias gets phase-specific spec mechanism with active firing): REJECTED on perfunctory-satisfaction grounds. 21-04-00 Section 6 explicitly warned: "Mechanical enforcement risks perfunctory satisfaction (the same trap the Inversion mechanism fell into when it considered REPAIR/REORGANIZE alternatives but rejected them without engaging the framing-flip option). The corrective is at the awareness level — apply as a cognitive habit, not a checklist item." DEFERRED MC-ENHANCE-1 + MC-ENHANCE-2 are the candidate mechanism-level correctives at specific phases; they remain DEFERRED per Step 5 guardrail. The library doesn't preempt them.

- **Pure option γ** (discipline-process-extension only; substrate-bias entries added to existing per-discipline failure-modes lists; no cumulative library): REJECTED — fragments the cumulative library across disciplines + replicates content + loses cross-discipline discoverability. Each substrate bias would need to appear in 3-4 disciplines' failure-modes lists (per the multi-discipline manifestation pattern), violating DRY without operational benefit.

The hybrid α+γ threads the constraints: single cumulative library (α property) + optional discipline cross-references (γ property) + active-cognitive-habit operation (NOT β).

### 3. Operation semantics — "awareness" and "challenge"

**"Awareness"** in this context = **active cognitive habit at recognition signals**. Not passive availability (read-once, file-away) AND NOT mechanical engagement (check-the-box every step). The 21-04-00 corrective explicitly endorses this form: "apply as a cognitive habit, not a checklist item."

**"Challenge"** (the user's vocabulary: "everytime we will run it, it can challenge this") maps to the same active-cognitive-habit operation. The library's named biases provide ANCHORS for the runner's cognitive engagement; engagement happens at recognition signals during the run, not at procedural mechanical steps.

**The existing discipline failure-modes lists are the project's established model for active-cognitive-habit operation.** Sensemaking spec line 141 explicitly frames its 6 failure modes as: "Sensemaking fails in recognizable patterns. These are not checkpoints to execute at each phase — they are patterns to notice when they're happening, like recognizing when you're off-balance." The proposed library inherits this anti-mechanical form.

**Operational distinction between mechanical and cognitive-habit:**

| Property | Mechanical (rejected option β) | Cognitive habit (committed hybrid α+γ) |
|---|---|---|
| Firing | At every step procedurally | At recognition signals contextually |
| Verifiability | Mechanical check ("did the runner apply X?") | Pattern-recognition outcomes ("did the runner's output show X-pattern-aware reasoning?") |
| Risk | Perfunctory satisfaction (check-the-box without engagement) | Interpretive verification dependency (compliance requires interpretation) |

The cognitive-habit form is the project's established corrective form per 21-04-00 explicit endorsement + existing discipline failure-modes pattern.

### Why the 3-level taxonomy is structurally real (not just relabeled 2-level)

The strongest objection to the 3-level taxonomy is that substrate-bias and discipline-process-failure-mode are entangled — many discipline failures emerge from substrate biases; the taxonomy could collapse to 2 (substrate + manifestation).

The defense rests on structural-distinction-by-corrective-form. Each level has a distinct corrective:

- **Substrate-bias-corrective:** awareness handle (named meaning-node + library entry). Applied across disciplines.
- **Mechanism-corrective:** specific spec edit at a specific phase (e.g., innovate's "Prior-step never-generate variant" refinement). Applied within one mechanism.
- **Discipline-process-corrective:** per-discipline notice pattern (e.g., "deliberately test the most uncomfortable output"). Applied within one discipline's process.

These are different operational interventions. A library entry doesn't replace the discipline failure-mode entry; the discipline failure-mode doesn't replace the library entry. They operate at different abstractions. The 3-level taxonomy captures the distinction.

Concrete example: Innovate's Survival Bias failure-mode prevention says "deliberately test the most uncomfortable output with extra care" (discipline-process corrective). The library entry for the underlying Additive-fix bias says "INSPECT before fix-category-commitment" (substrate corrective). Different correctives for what is, at one abstraction, the same cause.
