### Cycle 4 — Probe S1 (terminal runtime-imperative block)

Old's lines 290–331 contain a `---- NOW SOLID INSTRUCTIONS START ----` marker followed by 4 numbered steps: State Mode + Entry; Run Cycles; Assess Convergence (with Jump-scan refinement); Final Deliverable (6-section map template).

This is the **runtime-driving block**. The LLM loading the reference at Step 0 reads through the framework, and at the END sees a discrete "now DO these 4 steps in order" imperative.

The new file has equivalent content distributed across:
- §3.1 (Step 0 declarations) ≈ Old Step 1
- §3.4 (canonical cycle) ≈ Old Step 2
- §4.2 (convergence criteria + jump-scan) ≈ Old Step 3
- §5.1 (Transform) ≈ Old Step 4

But there is no discrete terminal block in the new file. The runtime imperative is implicit.

**Is the gap load-bearing?**

YES. Three reasons:
1. The `---- NOW SOLID INSTRUCTIONS START ----` convention is a marker the LLM cognition relies on. Other discipline-reference files in the project use similar terminal-instruction patterns (visible in sense-making, decompose references). Removing it diverges from project convention.
2. LLM cognition under load benefits from "do these N steps in order" at the end of a long reference file. Distributing the same content across multiple sections requires the LLM to re-assemble the imperative at runtime.
3. The Final Deliverable's 6-section template (Territory Overview / Inventory / Signal Log / Confidence Map / Frontier State / Gaps and Recommendations) in old's solid-instructions block IS preserved in new's §5.1 — but without the "do this NOW" framing, it reads as documentation rather than instruction.

**Mitigation:** add a terminal "Execute the Exploration Process" solid-instructions block to the new file, after §8 Summary. Bounded edit; ~30 lines.
