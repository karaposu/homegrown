### Critical boundary anchors from the specs

- `/reflect` explicitly says: *"Critique evaluates CANDIDATES — ideas, plans. Reflection evaluates the PROCESS — how S, I, C each performed."* → Hard boundary: candidate-evaluation = critique; process-observation = reflect.
- `/td-critique` explicitly requires constructive output on REFINE: *"Direct back to innovation with targeted feedback. Output: Which dimensions failed + what 'right' looks like on those dimensions."* → REFINE includes prescription of correction direction.
- `/td-critique` explicitly requires seed extraction on KILL: *"Extract a seed from the failure: 'this approach died because of X. What if an approach existed that didn't have X?'"* → KILL includes generating the new-direction seed.
- `/innovate` excludes: *"Innovation is not Brainstorming (brainstorming generates volume; innovation generates viability) — Optimization (optimization improves within a known space; innovation changes the space)."* → /innovate must CREATE something new, not refine existing.
- `/sense-making` includes a Definitional/Internal-Consistency perspective: *"Does this interpretation contradict any established definitions, principles, or prior stabilized models WITHIN the inquiry's frame? ... if a weak anchor (observation, single data point) contradicts a strong anchor (definition, tested principle), the weak anchor must justify the override."* → Checking claims against existing established structures is sensemaking territory.

## 3. Candidate Boundary Tests (Signal-First Probe)

From the spec evidence, several operational tests emerge for adjudicating "which discipline does this move belong to?" The strongest tests:

**T1 — Output-Shape Test.** What kind of artifact does the move PRODUCE?
- Novel content (a new idea, concept-name, edge-case, novel combination, novel condition) → `/innovate`
- An evaluative verdict on a candidate (with optional constructive direction) → `/td-critique`
- A process-observation about how S/I/C performed → `/reflect`
- An anchor / stabilized meaning / ambiguity-collapse → `/sense-making`
- A predictive model of an artifact's behavior → `/comprehend`

**T2 — Input-Type Test.** What does the move take as input?
- A seed (a question, gap, signal, dissatisfaction) → `/innovate`'s starting point
- A candidate or set of candidates → `/td-critique` evaluates
- A completed run's outputs (S.md, I.md, C.md) + human interventions → `/reflect` observes
- Vague/ambiguous input + the cognizer's understanding → `/sense-making` stabilizes
- An opaque-but-observable artifact → `/comprehend` models

**T3 — Order-in-Loop Test.** When in the SIC(R) pipeline does the move fire?
- Pre-evaluation, during candidate-creation phase → `/innovate`
- Post-creation, during candidate-evaluation phase → `/td-critique`
- Post-everything, second-order observation → `/reflect`
- Pre-candidate, during problem-understanding phase → `/sense-making`
- Anywhere model-of-an-artifact is needed → `/comprehend`

**T4 — Content vs Process Test.** What is the move TARGETING?
- The content under inquiry (the problem's substance) → `/innovate`, `/td-critique`, `/sense-making`, `/comprehend` (different aspects)
- The PROCESS that produced the content → `/reflect` exclusively

**T5 — Novel-vs-Existing Test.** Is the move creating something new OR responding to something already produced?
- Creating something that didn't exist → `/innovate`
- Operating on existing candidates → `/td-critique`
- Operating on existing process traces → `/reflect`
- Operating on existing claim/ambiguity to stabilize meaning → `/sense-making`

These five tests are the operational boundary framework. Sensemaking should refine and commit them as the inquiry's boundary anchors.
