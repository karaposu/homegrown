### Region C — `cognitive_harness/innovate/references/innovate.md` (criterion; D2; in-context)

The canonical `/innovate` reference. ~442 lines. Defines what Innovation is specified to do.

**C1 — Seven mechanisms.** Four Generators (Combination, Absence Recognition, Domain Transfer, Extrapolation) + three Framers (Lens Shifting, Constraint Manipulation, Inversion). Each mechanism has a "How to apply" sub-section and a "What it misses" sub-section.

**C2 — Inversion mechanism (canonical text).** Adjacency-fact: the reference defines Inversion as *"Assumes the opposite of a current belief and explores what follows. ... Identify a core assumption or belief related to the seed. State the opposite explicitly. Ask: 'If this opposite were true, what would follow?'"* Includes a depth-check refinement: *"After each inversion, ask 'Can I invert AGAIN?' The first inversion often produces an incremental improvement. The second often reveals a structural change. Keep inverting until you reach a statement about the SYSTEM, not about a COMPONENT."*

**C3 — Coverage strategy.** Minimum coverage: 1 Generator + 1 Framer per seed. Full coverage: all seven mechanisms applied. Convergence signal: when 3+ mechanisms point to the same innovation. **C3-adjacency:** the coverage rule is per-seed, not per-piece. When Innovation operates in Production-task mode (one seed unfolding into N pieces), the per-piece mechanism application is not separately gated by the coverage rule.

**C4 — Five tests.** Novelty / Scrutiny survival / Fertility / Actionability / Mechanism independence. **C4-adjacency:** the Scrutiny-survival test reads *"Does it hold up when challenged? What's the strongest objection, and does the idea survive it?"* The test as written evaluates a single candidate against its strongest objection; it does not require that an alternative candidate (the inversion-candidate) be generated and tested against the first.

**C5 — Failure modes (six).** Premature evaluation / Single-Mechanism Trap / Early Frame Lock / Innovation Without Grounding / Mechanism Exhaustion / Survival Bias.

**C6 — Single-Mechanism Trap (canonical text).** Adjacency-fact: *"Only one mechanism is used. The innovation space is barely explored. Whatever that mechanism produces is taken as 'the answer.'"* Prevention: *"Minimum coverage rule — always apply at least one Generator and one Framer."* **C6-adjacency:** the failure-mode definition is about TOTAL mechanism count per seed (less than 2). It does not address the case where multiple mechanisms are applied across pieces but all converge on the same direction at a specific decision-piece.

**C7 — Early Frame Lock (canonical text).** Adjacency-fact: *"The first successful reframe is adopted permanently. No further mechanisms are applied. The innovation is real but suboptimal — a better version exists in an unexplored region. ... An idea was accepted on the first successful mechanism application. The feeling is 'good enough, let's move on.' ... After the first successful output, apply at least one more mechanism to check if there's something better."* **C7-adjacency:** the failure mode is about adopting the first successful reframe permanently and not applying additional mechanisms. The prevention is "apply at least one more mechanism."

**C8 — Survival Bias (canonical text).** Adjacency-fact: *"Only the most comfortable or familiar novel outputs survive testing. Truly disruptive innovations are killed because they're uncomfortable, not because they're wrong. ... Everything that survives testing is incremental. ... Deliberately test the most uncomfortable output with extra care. Ask: 'Am I rejecting this because it's wrong, or because it's threatening?'"* **C8-adjacency:** the failure mode is about uncomfortable candidates being KILLED unfairly during testing. It does not directly address uncomfortable candidates being NEVER GENERATED — the prior-step failure of which Survival Bias is the downstream symptom.

**C9 — Assembly Check + Axis Coverage Check.** Adjacency-fact: Assembly Check fires *"After testing individual outputs"* — examines survivors and refined candidates together for emergent assemblies. Axis Coverage Check fires *"Before producing the assembly verdict"* — examines candidate set for orthogonal axes. Both operate over candidate SETS at assembly time. **C9-adjacency:** neither check fires at piece-level for piece-internal decisions. If a piece-internal decision (like "REFINES vs CORRECTS within Changes-from-Prior") is made with only one candidate generated, both checks pass the piece trivially.

### Gaps (within the bounded territory; all interpolable from neighbors)

This is the load-bearing sensemaking question for the next discipline.

### Frontier questions handed off to downstream disciplines

For **sensemaking** (next in pipeline):

1. **What is Innovation's "piece-level responsibility surface"** — does Innovation own the within-piece candidate-generation independently of the piece-list it inherits, or does Innovation's responsibility stop at "fill the piece with text using whatever mechanisms produce text"? The `/innovate` reference defines mechanisms per-seed; this case shows mechanisms applied per-piece. The boundary needs to be made explicit before maintenance candidates can be proposed.

2. **What is the relationship between the existing failure modes (Early Frame Lock; Survival Bias) and this specific case?** Early Frame Lock seems to fit: the layer-shift framing was the first successful mechanism application and was adopted permanently (no further mechanism — specifically no Inversion — was applied to question it). Survival Bias seems to fit a prior-step version: the comfortable candidate (REFINES preserves prior work) was never challenged because the uncomfortable alternative (CORRECTS — the prior is wrong) was never generated. Both apply but at different grain than the spec describes.

3. **Is Inversion's "depth check" (the canonical refinement note in `/innovate` reference §3 Inversion) the load-bearing missing application here?** The depth-check says "after each inversion, ask 'Can I invert AGAIN?' ... Keep inverting until you reach a statement about the SYSTEM, not about a COMPONENT." Applying Inversion at piece-level to the meta-lesson's own vocabulary (as `12-45` did) is a SYSTEM-level inversion: not "what if this argument is wrong?" but "what if this framing's own vocabulary is the trap?" The corrected inquiry reached SYSTEM-level Inversion; the weak prior reached only component-level (used Inversion on a different piece, not on the relationship-declaration framing).

4. **Does the case instantiate Gap-1 (T2 framer-suite under-elaboration per the prior gap-analysis) cleanly, or does it reveal a refinement to Gap-1?** The prior finding names Lens Shifting alone as too broad for nine sub-types. This case is tagged "wholesale rejection + redo." But the corrected inquiry's actual mechanism was Inversion applied to the inquiry's own meta-vocabulary — not Lens Shifting at all. Refinement candidate: Gap-1 may be misattributed; the missing piece is not necessarily a Framer-suite expansion but a piece-level Inversion-on-self-vocabulary application rule.

5. **Is there a "within-artifact self-application requirement" that Innovation should enforce?** The case shows that when Innovation introduces new vocabulary in a piece (the layer-shift framing in P4.2's meta-lesson), the same piece should apply that vocabulary to its own case as the first test. `12-45`'s Innovation enforced this with P3.7 (worked example) + P3.8 (self-reference acknowledgment). `12-15`'s did not. Is this a new failure mode or a sub-aspect of Early Frame Lock?
