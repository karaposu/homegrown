## (4) R4 — Existing innovate spec features A1 orchestrates

From `cognitive_harness/innovate/references/innovate.md`:

**Feature 1 — Inversion mechanism with depth-check refinement (§3):**
- Spec text: *"Identify a core assumption or belief related to the seed. State the opposite explicitly. Ask: 'If this opposite were true, what would follow?'"*
- Depth-check refinement: *"Keep inverting until you reach a statement about the SYSTEM, not about a COMPONENT."* Three depth levels named: Level 1 (component-level / workaround); Level 2 (system-level / architectural solution); Level 3 (root-cause-level).
- **A1 orchestrates this when:** the inherited assumption is detected; A1 forces Inversion to system-level depth specifically against that assumption.

**Feature 2 — Constraint Manipulation mechanism (§4):**
- Spec text: *"For each constraint, ask: 'What if I removed this?' AND 'What if I added a new constraint?'"*
- Both-direction mandate is in the AND — but Pair 9's B2 candidate makes it explicit/required.
- **A1 orchestrates this when:** the inherited frame's central constraint is detected; A1 forces Constraint Manipulation REMOVE on that constraint specifically.

**Feature 3 — Absence Recognition mechanism (§5):**
- Spec text — patch-level questions: *"What's missing? What should be here but isn't? Who needs something that doesn't exist yet? What would the complete picture look like?"*
- Spec text — redesign-level question: *"What would exist if this were designed from scratch today? What data, interface, or contract SHOULD exist between these components but was never created — because the system evolved incrementally?"*
- Both-level mandate: *"Both are valid."*
- Pair 4's W1 extends redesign-level with bidirectional refinement.
- **A1 orchestrates this when:** the inherited design is detected; A1 forces AR redesign-level on the seed's design specifically.

**Feature 4 — Lens Shifting mechanism (§2):**
- Spec text: *"Asks under what different conditions the idea becomes valid/powerful."*
- **A1 orchestrates this when:** the inherited success-criterion is detected; A1 forces LS on that success-criterion specifically.

**Feature 5 — Axis Coverage Check refinement (Phase 3 Test):**
- Spec text: *"Single-axis candidate sets often arise from a frame inherited from upstream pipeline stages; the axis-coverage check counters that bias."*
- **This is the spec's OWN explicit acknowledgment of the inheritance problem.** The check fires at Phase 3 Test (Assembly Check); A1's location is between Phase 2 Generate and Phase 3 Test, complementary to this existing check.
- **A1 orchestrates this when:** the candidate set's axis-coverage is single-axis (i.e., all outputs along one axis); A1 augments by forcing additional-axis candidate generation BEFORE Assembly Check.

**Critical insight:** Feature 5 (axis-coverage check) is the spec's existing inheritance-counter. A1 isn't replacing it — A1 fires EARLIER (between Phase 2 and Phase 3) and is BROADER (detects any single-shared-assumption pattern, not just single-axis variance). A1 + axis-coverage check form a 2-step detection: A1 catches inheritance at generation-output boundary; axis-coverage check catches inheritance at assembly time.
