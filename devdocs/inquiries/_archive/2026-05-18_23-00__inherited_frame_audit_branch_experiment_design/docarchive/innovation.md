### Q4 — Evaluation gate text

**Mechanisms applied:** Combination (single-run + cross-run components) + Extrapolation (forward-looking thresholds).

**Principal candidate text (Q4 committed):**

> **§ Inherited Frame Audit — Evaluation Gate.** A1's calibration is measured through a hybrid gate combining single-run observability with cross-run marginal-value validation.
>
> **Component (a) — Single-run observable (immediate calibration).** Per Innovation run, two rates are observable:
>
> - **False-positive rate.** Count of A1 firings where the override was correctly invoked (the frame was legitimately committed; no frame-alternative was structurally warranted). A high false-positive rate over multiple runs signals the predicate is too loose — typical causes: predicate identifies non-load-bearing assumptions as central; piece-level scope expanded beyond Q2's 4-property + Pair 7's 5th property criterion.
>
> - **False-negative rate.** Count of post-run user corrections (verbal or written; in the inquiry's _branch.md history; in a follow-up correction inquiry) that target inheritance A1 SHOULD have caught but didn't fire on. A high false-negative rate signals the predicate is too strict — typical causes: predicate's "explicit challenge" criterion misses implicit challenges; piece-level scope under-covered (some load-bearing commitments not in meta-decision-piece set).
>
> Both rates are observable per run by examining the Innovation output's mechanism log + override invocations + post-run human interventions.
>
> **Component (b) — Cross-run comparison (marginal-value validation).** Compare /innovate runs operating under two configurations:
> - **Baseline:** /innovate with composed refinement-set v3 + B1-B4 + V1-V4 + W1-W3 + W1-Pair4 (the 14 within-existing-structure refinements; no A1).
> - **Experimental:** Baseline + A1.
>
> Run the same inquiry seed in both configurations (or run different inquiries in matched configurations). Measure across 3-5 such matched pairs:
> - Does A1 catch inheritance cases that the baseline misses? (A1's marginal catch.)
> - Does A1 produce false-positives that the baseline doesn't have? (A1's marginal cost.)
> - Net marginal value = catches gained − false-positives introduced.
>
> Promotion criterion (heuristic): if marginal value is consistently positive across 3-5 matched pairs, A1 graduates from branch-experiment to actionable spec. Inconsistent marginal value (some matched pairs show value; others show false-positive surge) → recalibrate predicate before promotion.
>
> **Reciprocal relationship between components.** Single-run observable provides per-run immediate signal for calibration adjustment. Cross-run comparison provides cumulative-evidence for promotion. They're not redundant: single-run catches calibration drift per run; cross-run validates structural value across runs.
>
> **Thresholds are evidence-quality-driven, not count-based.** The gate intentionally does not commit to "X% false-positive is acceptable" or "Y matched pairs justifies promotion." These are heuristics dependent on case-specific evidence quality (was the false-positive a structural mistake or a borderline case? was the marginal value strong or weak?). The calibration is per-run evaluator judgment, informed by the established pattern from the composed refinement-set v3's override-rate calibration discipline.
>
> **Promotion path.** When evaluation gate shows consistent marginal value + acceptable false-positive rate across 3-5 matched pairs, the next /innovate redesign inquiry promotes A1 from branch-experiment to actionable spec edit and commits the spec text (Q1-Q5) into /innovate reference.

**Layer-2 Inversion-candidate:** What if evaluation gate is SINGLE-RUN ONLY (drop cross-run comparison)?
- *Pros:* faster feedback loop; no cumulative-evidence delay.
- *Cons:* per Pair 9's hint, cross-run comparison is the marginal-value validation; without it, A1's structural value isn't measured.
- **Verdict:** keep hybrid; cross-run is the validation gate.
