## Phase 3 — Ambiguity Collapse

### A1: Candidate enumeration choice

**Counter-interpretation:** Pure Candidate D (clause-preservation alone) is structurally simplest and catches H1 most directly. Why add meta-categories at all?

**Why counter fails (structural grounds):** Clause-preservation operates AFTER _branch.md is written; meta-categories operate DURING writing. They serve different purposes — guided-thinking vs structural backstop. Pure D leaves the writing step unguided; the agent might write a one-sentence Question that happens to miss aspects the user mentioned without conjunctions. Meta-categories prompt structured thinking pre-write. Both needed.

**Confidence:** HIGH.

**Resolution:** Candidate E (Hybrid: 5-cat + clause-preservation backstop).

**Fixed:** 5 meta-categories for Question; clause-preservation fail-safe.

**Excluded:** Pure D, Candidate C (Constraints overlaps Scope Check section).

### A2: Fail-safe selection

**Counter-interpretation:** Just FS1 — single fail-safe, less complexity.

**Why counter fails (structural grounds):** FS3 (Source Input section in _branch.md) is INDEPENDENT of FS1's trigger. FS1 catches at creation; FS3 enables audit AT ANY DOWNSTREAM STAGE. Different purposes. The complexity addition is one new section in template, not a runtime mechanism — cheap.

**Confidence:** HIGH.

**Resolution:** FS1 + FS3 (skip FS4; defer interactive).

### A3: Graceful degradation phrasing

**Counter-interpretation:** Always require explicit sub-field listing — most robust.

**Why counter fails:** Bloat for simple inputs (single subject + single action + single target). The "CHECK not required sub-fields" policy preserves robustness for complex inputs without taxing simple ones.

**Confidence:** HIGH.

**Resolution:** "Meta-categories are a CHECK on what well-framed question contains, not required sub-fields. If user's input maps cleanly to one sentence covering all 5, write that sentence. If multi-clause or multi-part framing, list aspects explicitly."

### A4: ROOT-only vs ROOT+BRANCH

**Counter-interpretation:** MC2 mentions `cognitive_harness/protocols/branch_inquiry.md` as "optionally" — including it now is straightforward.

**Why counter fails (structural grounds):** _branch.md Subject explicitly scoped to `cognitive_harness/MVL+/SKILL.md` Step 3 of "If NEW". The Layer Commitment names "framework-artifact instruction's SHAPE...inside one step." Expanding scope to a second file mid-inquiry would violate the committed Subject. MC2's "optionally" allows future expansion; this inquiry's scope is fixed.

**Confidence:** HIGH.

**Resolution:** ROOT-only this inquiry; BRANCH inquiry creation as Next Actions COULD.

### A5: Goal-field decomposition

**Counter-interpretation:** Goal wasn't implicated in H1; leave alone.

**Why counter fails:** Goal CAN fail similarly (drop a criterion, drop a use case). 4 sub-prompts (Criterion / Use Case / Desired Outcome / What Would Fail) is cheap; marginal cost is small; downstream value is real (better-framed Goals → better downstream discipline anchors).

**Confidence:** MEDIUM-HIGH (not H1-implicated; extension based on plausible-failure-mode reasoning).

**Resolution:** Goal decomposed lightly with 4 sub-prompts.

### A6: Source Input section in _branch.md

**Counter-interpretation:** CONCLUDE already preserves raw input in finding.md; duplicates.

**Why counter fails (structural grounds):** Timing matters. _branch.md is read by every downstream discipline at every stage; finding.md is read at end. Source Input in _branch.md eliminates the transcription-loss failure surface for the entire downstream cascade. The "duplication" is intentional + cheap (one section, raw text).

**Confidence:** HIGH.

**Resolution:** Source Input section in _branch.md committed.

### A7: Branch-experiment gate threshold

**Counter-interpretation:** ≥3 of 5 is arbitrary; ≥4 of 5 would be more rigorous.

**Why counter fails:** ≥3 of 5 is what MC2 itself specifies verbatim. Honoring the authoritative source. ≥4 of 5 would be tighter but slower-to-evaluate; ≥3 of 5 balances speed vs confidence per LOOP_DIAGNOSE Step 5 monitoring proposal (5-10 chains minimum).

**Confidence:** HIGH.

**Resolution:** ≥3 of 5 per MC2 verbatim.

**Why counter fails (structural grounds):** Authorship-bias mitigation requires anchoring to an external source. MC2 is the load-bearing external source (authored at LOOP_DIAGNOSE, which itself was diagnosed against the user's correction — externally grounded by the user).
