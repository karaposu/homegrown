## Phase 2 — Perspective Checking

**Technical / Logical (guard a — the always-vs-theater steelman at FULL strength):** *"The high-stakes conditional is wisdom: a 21-variation grid on a trivial piece is ritual; forced grids produce filler that passes no test — mechanism-theater. The real fix is honest telemetry, not maximal defaults."* Engaged seriously, and the collision produces the design's central move: **the theater-risk is real ONLY if full-scale mandates surviving variations.** Redefine the floor as **TESTED, not surviving** — every mechanism must FIRE and its output must enter the 5-test cycle, where an immediate kill is a legitimate, two-line, recorded outcome (`Inversion: fired — 'X'; killed at novelty`). Under that floor, a mechanism with nothing to say costs two honest lines, not a page of filler — firing is cheap, faking is pointless, and the spread-guarantee (the reason the seven exist: "so you don't miss the best idea by only looking in one direction") is preserved. The steelman's telemetry-instinct is also kept: the ledger makes every fire and every kill VISIBLE. What does NOT survive the collision: the stakes-conditional as a self-serve escape (who judges "high-stakes"? the same session that wants to go home early — exactly the self-relaxation the house forbids elsewhere). **Resolution: all-seven-fired becomes UNCONDITIONAL; depth (the 3-variation grid) applies at the run's CORE; skips exist only via the user's own words.** If the user wants the literal 7×3 everywhere instead, the finding prices it (~300–450 lines/run) and the text carries a one-line toggle — presented, not chosen for them.

**Definitional (guard b — the variation-quality floor):** a variation is non-filler iff it carries a TEST DISPOSITION — generated AND entered into the 5-test cycle, with its outcome recorded (survived / refined / killed-at-<test>). The ledger's row format enforces this: no disposition, no credit. "Tested-and-killed" is the honest cheap case; "untested prose" is the defect.

**Risk / Failure (guard c — the checker):** without a mechanical gate the ledger is self-attested — but the CONCLUDE precedent shows template-required sections still bite (absence is glanceable by the user in two seconds). The checker build (~30 lines of bash: innovation.md has the ledger section; 7 mechanism rows present; each row carries FIRED/SKIPPED; SKIPPED rows carry a quoted-user-words field; the telemetry verdict consistent) closes the gap mechanically — ROUTED, change-gated, alongside the spec edit. Honest note: the checker was ALWAYS missing for every discipline; building the innovation mode first is the wedge.

**Human / User:** the user's underlying want is ASSURANCE — never again discovering compression by asking about run-times. The ledger delivers that even before the checker: seven rows, each accountable, every skip carrying their own quoted words or standing out as a violation.

**Strategic / Long-term (placements):** L1 → ONE reconciled paragraph replacing BOTH SKILL.md instruction 2's coverage sentences AND the reference's "Minimum/Systematic coverage" passage (same words in both — one standard); L2 → the seed-narrows-never-coverage rule INTO SKILL.md (binds every runner) + a reinforcement note in traverse's step 2; L3 → the Mechanism Coverage Ledger as a required output section (spec'd in both files; piece-mode reuses the existing per-piece mechanism log format); L4 → the telemetry section gains the ledger FLAG condition (mirroring the mode's existing FLAG — the pattern is already in the file).

**Frame-exit check:** could the fix live ONLY in the runner (traverse instructing full-scale every time)? No — the leak-map shows the runner was the leak's carrier; binding only the carrier leaves the next runner free. The skill must self-defend.

**Phase:** text delivered by this inquiry; the apply (both spec files + the traverse note + optionally the checker) on the user's word.
