## Phase 2 — Generate (7 mechanisms × 3, compact)

### 1. Lens Shifting (Framer)

- **1G — the KANBAN BOARD as the one-screen visual (adopted).** The selections file rendered as columns: **FIELD** (backlog — `_route.md`, everything routelister found) → **PARKED** → **ADMITTED** (the ready column — the user's waiting queue) → **IN-FLIGHT** (≤N) → **DONE/REMOVED**. The Selector moves cards left↔right with reasons; the Dispatcher only pulls ADMITTED→IN-FLIGHT when a slot frees; the Navigator restocks the backlog. One picture, whole design — and it renders "not priority-ordered" naturally (a column is a set, not a ranking).
- **1F — ATC continuity (one line).** From the prior story: the tower stops doing ground-ops — it now only grants *flight plans* (admission); pushback and takeoff are automated ground systems (the code Dispatcher). The metaphor UPGRADES rather than replaces.
- **1C — the "you just rebuilt Jira" deflater (adopted as an aside).** Answer: deliberately — kanban/two-level scheduling are *convergent* workflow shapes; the novelty is what flows through (typed routes → inquiries → findings) and the **invalidate-if revision discipline** most boards lack (cards here know what discovery voids them).

### 2. Combination (Generator)

- **2G — the selections file × the turn-record = ONE commitment artifact (adopted — the deepest unification).** The Turn Architecture finding's turn-validity demanded: field-written-before-choice · choice+rationale · outcome slot · the goal. The selections file delivers all four BY CONSTRUCTION: the field is `_route.md` (written by other stations before admission); the admission entry IS choice+rationale; the status trail + completion pointer IS the outcome slot; entries reference the goal. **Turn-validity stops being a discipline and becomes a side-effect of using the artifact.**
- **2F — invalidate-if × the corpus's corrigenda machinery (adopted).** Findings already carry `impacted_by:`/corrigenda; invalidate-if is the same revision discipline applied to *decisions*: grooming is corrigenda-for-selections. The project already practices this — on findings; the design extends it to commitments.
- **2C — Navigator × the dial (minor note).** A Navigator run can double as the fresh-eyes field for a heavy admission session — one run, two purposes (operation-difference AND objectivity served together when convenient).

### 3. Inversion (Framer; at the meta-decisions)

- **3G — invert the recommendation: when would D1 (single session) be the RIGHT end-state?** Only if N stays 1 forever and runs stay short — i.e., if the sustained-parallel-traversal goal is abandoned. Since SUSTRALL/the Expedition commit to sustained, eventually-parallel operation, **the cadence-split is entailed by the committed goal**, not by taste. Adopted: the recommendation *derives* from canon, and the finding should say so.
- **3F — invert the one-file verdict: what breaks with ONE selections file?** (i) Write-contention — prevented by single-writer (only the Selector writes; the Dispatcher flips status/appends pointers in marked fields). (ii) Unbounded growth — solved by archiving DONE/REMOVED entries to a yearly archive section/file (the live file stays small). Holds, with the archive note. Adopted.
- **3C — invert the valve: what if EVERYTHING ends up needs-judgment?** Then the code Dispatcher fires nothing and the Selector decides per-dispatch — which IS D2 (the session-dispatcher). So **D2 and D3 are not rival designs but endpoints of one continuum, with the valve-rate as the dial**: low valve-rate → you're living in D3; saturated → you've degraded gracefully into D2 (and should improve annotations). The "fallback" is built-in degradation, not a fork. Adopted — this dissolves the map's one remaining either/or.

### 4. Constraint Manipulation (Framer; both directions)

- **4-ADD (generic, adopted).** Every design in the map gets a **"choose this when"** clause — D1: solo manual short-horizon; D4: you want durable revisable selections but still one seat; D3: parallel runs or long horizons; D2: you're in D3 and the valve saturates; D5: never (shown why).
- **4-ADD (focused, adopted).** The growth path gets **observable trigger sentences**: → D4 *now* (the artifact costs one file); → split the Dispatcher *the first time you actually want two loops in flight*; → schedule the first Navigator run *when a loop-tail feels locally blind or the index carries ≥K stale entries*.
- **4-REMOVE (generic).** Drop invalidate-if (simpler entries)? → grooming becomes re-derivation (expensive) or neglect (rot); the triple is load-bearing. KILL the simplification.
- **4-REMOVE (contrarian).** Drop the Navigator from the end-state (loop-tails only)? → local blindness accumulates (the routelister-gap finding's exact warning) and the index never gets maintained. Keep — with a *sparse cadence* note (the Navigator is recurring, not frequent).

### 5. Absence Recognition (Generator; both levels, bidirectional)

- **Patch-level:** (i) **WHO performs the stations today (adopted — the adoption insight):** at Level 1 the human IS all three stations — the design names the *hats you already alternate between* (sometimes you survey the map; sometimes you decide what deserves running; sometimes you just fire the next thing). Adoption is *renaming and recording*, not rebuilding. (ii) **The needs-grooming inbox:** completion pointers and `failed` statuses and valve-surfaced entries all land in one place the Selector reads next time it sits down — the mechanical wake-plumbing (one line). (iii) **Failure handling:** `failed` completions go to the inbox; the Selector decides retry/park/remove (consistent with the prior finding's Runner-reports-Selector-decides).
- **Redesign-level:** none — the five-piece shape holds.
- **Bidirectional (already-present):** today's `devdocs/next_steps_for_sustrall.md` worklist + the Expedition's ledger sketches are **proto-selections files** — the design formalizes an existing habit, which is why D4 is cheap.
- **Patch (failure poles, adopted):** the prior story named stagnation (never fires) and explosion (never stops); the queue adds the third: **ROT** (stale commitments — the wall of dead tickets). The design's grooming triggers exist precisely to hold off rot. The triad — **stagnation / explosion / rot** — bounds the whole operating space.

### 6. Domain Transfer (Generator; native source included)

- **6-native (adopted).** The corpus's own **GATED-on(condition)** vocabulary (from the deferred-vs-gated finding) IS the run-condition language — the queue's condition fields reuse an already-canonized notation; nothing new to invent.
- **6-different (the spine, already seated).** Two-level scheduling (OS) + kanban (the visual). A third domain (CI/CD pipelines) — REJECTED, metaphor budget.

### 7. Extrapolation (Generator)

- **7G — the ladder tie (adopted).** At Level 2+, admission is exactly what graduates: the Selector *proposes* admissions, the human approves — and the selections file's rationale trail IS the agreement-data the graduation gates need. At L3, scoped self-admission. The Dispatcher stays fixed code at every level; the Navigator stays schedulable. The architecture is the autonomy climb's substrate.
- **7F — memory hygiene at scale (one line).** The Navigator's stale-flagging is what keeps a years-long corpus navigable — index maintenance is long-term memory hygiene, not bookkeeping.
- **7C — the rot pole (folded into 5-patch).** Named above; the triad closes the failure space.
